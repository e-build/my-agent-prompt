코드에 주석을 쓸 때 따르는 규칙이다.

적용 범위
- 이번 작업에서 직접 추가하거나 고친 주석만 대상으로 한다. 원래 있던 주석과 주석 외 코드는 건드리지 않는다.
- 사용자의 명시적 요청과 프로젝트 규칙(AGENTS.md, 린터 설정)이 이 규칙보다 우선한다.

1. 기본값은 주석 없음
코드와 이름만으로 읽히면 주석을 쓰지 않는다. 아래는 쓰지 않고, 썼다면 지운다.
- 코드를 말로 반복하는 주석 (`// 사용자 조회`)
- 변경 과정 서술 (`// 기존 로직 유지`, `// X에서 Y로 변경`, `// 새로 추가`)
- 사용자나 리뷰어에게 하는 말 (`// 요청하신 대로 수정`)
- 구획용 배너와 구분선, 주석 처리된 코드

2. 허용되는 주석
a. 문서 주석: 클래스·인터페이스 같은 타입 선언과, 타입이 공개하는 함수·메서드 선언에 쓴다.
   - 타입 선언에는 이름만으로 알 수 없는 책임, 불변식, 쓰임새가 있을 때 쓴다.
   - 공개 함수·메서드에는 시그니처로 알 수 없는 계약(전제조건, 부수효과, 예외, 단위, 스레드 안전성)이 있을 때 쓴다.
   - 이름과 파라미터를 풀어쓰기만 하는 문서 주석은 쓰지 않는다.
b. 이유 주석: 코드만 보면 잘못됐거나 불필요해 보이는 부분에 한해 위치와 무관하게 쓴다. 외부 버그 우회, 순서 의존, 의도적 예외 처리, 성능상 선택이 해당한다.
c. 테스트의 `// given`, `// when`, `// then`: 같은 파일이나 주변 테스트가 이미 쓰고 있을 때만 쓴다.

3. 작업 맥락은 주석에 남기지 않는다
주석은 코드의 현재 상태만 설명한다. 작업번호와 티켓번호, 계획 문서의 단계명("Step 2", "Phase 1"), 문서 경로, 날짜, 작성자는 적지 않는다. 이력은 커밋 메시지에 둔다.

4. TODO와 FIXME는 쓰지 않는다
남은 일은 주석으로 남기지 않고 최종 답변에서 알린다.

5. 지우지 않는 것
- 도구가 해석하는 주석: `eslint-disable`, `@ts-expect-error`, `noinspection`, `# noqa`, `//go:build`, 포매터 on/off, `// language=SQL`, 라이선스 헤더, shebang
- 미완성을 뜻하는 주석(`// ... 나머지 코드`, `// TODO: 구현`): 지우지 말고 사용자에게 알린다.

6. 남기는 주석의 형태
한 줄을 기본으로 하고, 파일의 기존 주석 언어와 형식을 따른다.
