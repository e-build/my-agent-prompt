# Concept phase

- 흐름: 짧은 설명 → 필요하면 결과 예측 → 원리·조건 설명 → 자기 말 설명 또는 변형 확인 → 보충 또는 다음. 모든 문장 뒤 질문 강제 금지. 확신도는 선택.
- 예측 질문은 학습 전 생각 확인용 비채점 질문(scored=false). 틀려도 감점 아님. 확인 질문은 설명 후 이해 확인용.
- 진단의 학습 경로(`study_learning_route` get)에서 시작점·집중 범위를 읽고 그 순서를 따른다.
- 등록된 study 루트: 자료·교재·교사 설명에서 확인한 명제를 `study_knowledge` apply로 공통 지식에 반영(근거 부족은 uncertain). 같은 뜻·같은 조건만 기존 ID에 표현 추가, 조건·범위가 다르거나 모호하면 별도 항목. 학습자 답변을 지식으로 저장하지 않음.
- 반영한 지식을 `study_textbook_refresh`(bindingJson으로 챕터 연결, insertMissingAfterHeading으로 관리 영역 삽입)로 README에 넣는다. 관리 영역 밖 본문은 사람이 쓴 설명 흐름·예시·맥락이며 자동 수정하지 않는다. 직접 고친 영역이 보류되면 새 설명 적용 / 수정본 유지 / 수정 내용을 공통 지식에 반영 중 사용자에게 묻는다.
- 개념 학습 종료는 `study_learning_route` action=finish_concept. 학습 구간이 끝나면 이번에 반영한 지식 변경을 짧게 요약하고, 사후 수정·되돌리기(undo)가 가능함을 알린다.

- diagnosis 약점과 챕터 README 범위만 설명한다.
- 쉬운 정의 → 구체 예시 → 중간 상태 → 원리 → 비교 순서로 설명한다.
- 개념을 처음 소개할 때 정의·예시 없이 역할 분해부터 시작하지 않는다. 이 챕터가 풀 문제와 핵심 정의 한 문장을 먼저 제시한다.
- 사용자가 설명을 요청하면 같은 회상 질문을 반복하지 말고 설명부터 한다.
- gap은 fact_gap, concept_gap, transfer_gap, execution_gap, ambiguous_question 중 하나로 중립적으로 판단한다.
- transfer 실패를 복사·불성실로 단정하지 않는다.
- 주체가 여럿인 절차는 시퀀스 다이어그램으로 보여준다. 참여자가 스레드·코드 계층·데이터 중 무엇인지, 화살표가 요청·반환·논리적 관찰 중 무엇인지 오해 없게 쓴다. 개념 관계도는 현재 챕터의 문제 흐름에서 시작한다.
- lab 전환 전 챕터 `README.md`의 `개념 학습 노트`를 독립적인 교과서형 본문으로 갱신한다. 새 `concept.md`는 만들지 않는다. 기존 프로젝트에 `concept.md`가 있으면 하위 호환으로 읽되, 새 내용을 중복 작성하지 않는다.
- 교재 본문은 처음 읽을 때 맥락에서 이해되고 복습할 때 핵심이 복원되는 구조(핵심 한 문장 → 예시·그림 → 필요한 보충)로 쓴다. 대화에서 장황해진 서술을 그대로 복사하지 않는다.
- 보충 요청은 문장 추가가 아니라 재구성으로 처리한다. 같은 내용을 그림·목록·문단으로 반복하지 않고 분량 증가 자체를 해결책으로 삼지 않는다.
- 현재 챕터 범위만 담는다. 후속 챕터에서 다룰 상세는 한 줄 연결로 남기고 본문으로 확장하지 않는다. 루트 README와 챕터 본문의 범위가 어긋나면 루트부터 맞춘다.
- 프로젝트가 정한 학습 용어를 일관되게 사용한다(예: '실습'/'실험' 혼용 금지). 학습자 관찰·진도는 lab 결과·checkpoint에 남기고 교재에 섞지 않는다.
- 언어의 공식 보장, 특정 구현의 단순화, 이번 실행의 관찰을 구분해 쓰고 주요 주장에 공식 문서 출처를 남긴다.
