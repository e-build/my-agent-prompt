# Book rebuild

챕터가 끝나면(시험 통과와 확인) 이 챕터에서 배운 것을 **내 교과서(book/)** 에 개념 단위로 재구성한다. 교과서는 지식백과가 아니라, 학습자가 나중에 이 챕터에서 이해한 흐름을 그대로 되살리는 글이다.

## 순서

1. `study_book` action=plan `{projectSlug, chapterSlug}`으로 이 챕터의 지식(명제)이 이미 속한 페이지(보강 대상), 미배치 명제, 재료 목록, 현재 위계를 확인한다.
2. 재료를 필요한 만큼만 읽는다: 챕터 `README.md`, 문제(진단·개념 확인·복습·시험의 질문과 채점 기준의 모범 답·해설), `lab/results.md`와 실습 코드.
3. 내용을 **개념 단위**로 나눈다. 한 챕터는 보통 개념 여러 개에 걸친다. 챕터 순서가 아니라 개념 위계에 맞춰 둔다.
4. `study_book` action=apply 한 묶음으로 적용한다: 필요한 하위 개념 `create`, 미배치 명제 `place`, 페이지 `write_page`, 모든 대상 페이지에 `record_learned`(projectId·chapterSlug·completedOn).
5. 적용 결과를 학습자에게 보고한다: 페이지마다 새로 씀/보강함/옮김, 무엇을 넣었는지 한두 줄, 적용 결과의 차이 링크(`차이:`), 되돌리기용 changeId(`undo`). 묻지 않고 바로 적용하는 것이 기본이다.

## 재구성 원칙

- 같은 개념 페이지가 있으면 **보강**한다. 새 내용을 기존 흐름 안에 녹이고 끝에 덧붙이지 않는다. 이미 있는 설명과 같은 말은 넣지 않고 새 관점·조건·예시만 더한다.
- 없으면 새로 쓴다. 다른 개념을 설명해야 하면 한 줄 요약과 그 페이지 링크만 쓴다.
- 지식(명제)은 한 페이지에만 속한다. 이미 다른 페이지에 있으면 그 페이지를 보강하거나 `move_member`로 옮긴다.
- 구조: 핵심 한 문장 → 설명(그림·Mermaid 가능) → 예시. 경로·하위 목록·관련 개념·배운 곳은 자동 영역이 만들므로 본문에 목록으로 쓰지 않는다.
- 다른 영역에 같은 주제가 있으면(예: 자바 인터럽트와 리눅스 시그널) `relate`로 연결한다. 본문에서는 차이를 설명할 때만 한 줄로 언급한다.
- 예시는 **근거가 있는 것만** 쓴다: 실제로 풀었던 문제(문제 → 모범 답·해설), 검증을 통과한 실습 step의 코드와 관찰 출력. 확인하지 않은 코드·출력은 만들지 않는다.
- 챕터 범위만 다룬다. 이 챕터에서 배우지 않은 내용을 새로 쓰지 않는다.
- 언어의 공식 보장, 특정 구현의 단순화, 이번 실행의 관찰을 구분해 쓴다.

## 하지 않는 것

- 학습자의 원래 답·오답·확신도를 넣지 않는다.
- 챕터 `README.md`를 그대로 복사하지 않는다. 뽑아서 다시 쓴다.
- 최상위 영역을 만들거나 사용자가 정한 개념의 이름·위치를 바꾸지 않는다. 필요하면 `propose`로 제안한다.
- 사용자가 직접 고친 본문을 덮어쓰지 않는다. apply가 거부되면 수정본을 받아들일지(`adopt_page`) 먼저 묻는다.
