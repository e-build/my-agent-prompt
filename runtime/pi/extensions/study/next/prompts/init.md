# 학습 프로젝트 초기화

학습 주제: **{{topic}}**

학습 주제는 위 문자열 전체다. 주제가 비어 있으면 프로젝트를 만들지 말고 `/study-init <학습주제>`로 다시 실행하라고 안내한다.

이 지침이 표준 구조를 정의한다. 외부 레퍼런스 프로젝트를 읽지 말고 주제에 맞는 실제 개념으로 채운다. 개발 주제는 예시 중 하나일 뿐이며 언어·운동·음악·경영·글쓰기·자격증·학문 등 모든 분야에 맞게 일반화한다.

## 흐름

1. 디렉터리 확정 → 2. 브리프 인터뷰(TUI) → 3. 자료 조사 → 4. 배치 진단(학습 채널) → 5. 문서 생성 → 6. 커리큘럼 승인(학습 채널) → 7. 등록

학습자에게 보내는 질문·커리큘럼 요약은 `study_ask`/`study_send`로만 보낸다. 브리프 인터뷰만 `ask_user_question`을 쓴다(프로젝트가 생기기 전이라).

## 1. 디렉터리

- `projectSlug`는 `study-{slug}` 형식. 소문자, 띄어쓰기→하이픈, 버전 숫자 유지. 한글 주제는 의미가 유지되는 짧은 영문 slug. 예: "영어 회화" → `study-english-conversation`, "Redis 7" → `study-redis7`.
- 기본 대상은 `cwd/projectSlug`. 사용자 지정 경로가 있으면 그 절대 경로.
- cwd나 상위가 이미 같은 학습 프로젝트면 그 루트를 재사용하고 중첩 생성하지 않는다. 기존 프로젝트 안에서 실행했다면 기존 커리큘럼 수정인지 신규 생성인지 먼저 확인한다. 기존 기록을 묵시적으로 덮어쓰지 않는다.
- 상위에 `.study/workspace.json`(study 루트)이 있으면 그 루트 바로 아래에 만든다. 홈 전체를 탐색하지 않는다.
- 파일을 만들기 전에 확정한 절대 `projectRoot`를 알린다. 이후 모든 도구에 같은 경로를 쓴다.

## 2. 학습 설계 브리프 인터뷰

`ask_user_question`으로 아래 4개를 한 번에 묻는다. 도구가 없을 때만 텍스트로 묻는다.

```text
1. 목적/성공 기준: 왜 배우고, 끝났을 때 무엇을 할 수 있으면 성공인가요?
2. 현재 수준(자기보고): 처음/용어만 앎/따라 해봄/실무 경험 있음/체계화 필요 중 어디에 가깝나요? 실제 시작점은 이어지는 짧은 배치 진단으로 함께 정합니다.
3. 범위/규모: 꼭 포함할 것과 제외하거나 가볍게 다룰 것, 선호 챕터 규모(짧게 3~5 / 표준 8~12 / 깊게 15+).
4. 참고 출처/환경: 원하는/피하고 싶은 자료. 기술 주제라면 스택, 버전, 로컬 환경 제약.
```

- 개별 개념 이해 여부는 묻지 않는다(배치 진단이 확인한다). 복습 간격은 묻지 않는다(+1/+3/+7/+14일 기본).
- 답을 5~8줄로 요약해 확인받는다. "알아서", "기본값"은 합리적 기본값으로 진행한다. 목적이 전혀 없으면 한 번만 더 묻는다.
- 확인 전에는 디렉터리·문서를 만들지 않는다.

## 3. 자료 조사

공식 문서, 대표 교재, 널리 쓰이는 강의·로드맵에서 학습 순서와 개념 의존성만 뽑는다(복붙 금지). 가능하면 최신 웹 검색을 쓴다.

산출물:
- 보편적으로 먼저 배우는 것, 선행·후행 개념, 헷갈리는 개념 쌍, 실제 판단으로 이어지는 순서
- **선수 갈래 3~5개**: 목표에 필요한 독립적인 능력 줄기와 각각이 필요한 이유 한 줄

## 4. 배치 진단 — 학습 채널

커리큘럼을 정하기 전에 실제 출발점을 확인한다. 점수가 아니라 **어디서 시작하고 무엇을 건너뛸지**를 정한다. 프로젝트 전체에서 이 진단 한 번뿐이다. 챕터를 시작할 때 다시 진단하지 않으므로, **챕터별 출발점까지** 여기서 정한다.

진행 규칙:
1. `study_ask`(purpose=placement, projectRoot 지정, 문항 1개)로 **한 번에 하나씩** 묻는다. 채점 기준은 이 도구가 먼저 저장한다. 답을 듣기 전에 기준을 말하지 않는다.
2. 갈래마다 **목표에 가까운 수준부터** 묻는다. 맞으면 다음 갈래, 틀리거나 모르면 한 단계 아래. 다음 질문은 직전 답을 보고 고른다.
3. 용어 정의가 아니라 **예측·판단**을 묻는다. 예: "스레드 두 개가 같은 변수에 `count++`를 10만 번씩 하면 결과는?"
4. 매 질문에 **확신도(0~10)** 를 함께 받는다(`askConfidence: true`). 기록할 때 학습자가 말한 값 ÷ 10을 `confidence`에 넣는다. 빠뜨리면 추측하지 말고 비운다.
5. 확신도는 판정을 바꾸지 않는다. 확신 7 이상의 오답은 오개념으로 보고 집중에 넣는다. 확신 3 이하의 정답은 건너뛰지 말고 압축해서 다룬다.
6. 답장이 오면 `study_answer_record`로 원문·도움 정도·판정을 기록한다. 설명해 준 갈래는 확인된 것이 아니다. 미응답은 unverified.
7. **최소 문항 수 없음, 상한 8문항.** 시작점과 건너뛸 범위가 정해지면 바로 끝낸다.
8. 해설은 문항마다 **질문 요지 → 내 답(원문) → 확신도 → 판정 → 정답·해설** 순서로, `study_send`(notice)로 보낸다.
9. 요약(시작점, 집중, 건너뛸 갈래와 근거, 미확인, 종료 사유)을 학습자에게 확인받은 뒤 `study_placement_finish`로 저장한다. 챕터 구성이 정해진 뒤 `chapters`에 챕터별 출발점(시작점·건너뜀·집중·미확인)을 넣는다. 챕터 구성 전에 먼저 저장했다면 5단계 뒤 같은 도구로 다시 저장한다.

경로 확정:
- 확인된 갈래는 챕터로 만들지 않거나 압축한다. 건너뛴 범위는 README `건너뛴 범위와 근거` 표에 남긴다.
- 미확인 갈래는 포함하고 그 챕터 출발점의 `unverified`에 적는다. 개념 학습 중 예측 질문으로 확인된다.
- 자기보고와 진단 결과가 다르면 둘 다 적고 진단 결과를 따른다.

## 5. 문서 생성

```text
study-{slug}/
├── README.md
├── AGENTS.md
├── SETUP.md
└── ch-{NN}-{영문-슬러그}/
    ├── README.md          # 학습 지도 (templates/chapter-readme 양식)
    ├── concepts/          # 개념 학습 때 개념 파일을 쓴다. 지금은 만들지 않는다
    └── lab/               # 실습 단계에서 만든다
```

### README.md

배치 진단으로 정한 시작점부터 목표까지 설계한다. 확인된 범위를 다시 가르치지 않는다.

- **학습 환경 세팅**: 안전한 개인 연습 환경. 실제 고객·운영·공유·위험 환경은 연습장으로 쓰지 않는다. 개발이면 로컬 샌드박스·Docker·포트 충돌 회피(예: 3307, 6380, 5433, 8081).
- **Phase 구성**: 기초 / 중급 / 고급 / 실전 틀을 참고하되 확인된 단계는 빼거나 압축한다. Phase마다 하위 주제와 상세 학습 목표.
- **커리큘럼 설계 근거**: 브리프, 배치 진단 결과(시작점·집중·미확인·문항 수), 대표 자료의 순서, 개념 의존성, 헷갈리는 쌍. 자기보고와 실제 확인을 같은 줄에 섞지 않는다.
- **건너뛴 범위와 근거**: 표(갈래 | 확인한 질문 요지 | 필요하면 볼 자료). 없으면 "없음".
- **개념 의존성 지도**: mermaid. 챕터 사이 선행 관계는 챕터 slug를 노드로 쓴 실선 화살표로 그린다(`/study-map`이 읽는다).
- **추천 학습 리소스**: 표.
- **학습 원칙 요약**: 직접 해 본다 / 주장에는 근거 / 실제에 가까운 분량 / 실패를 안전하게 재현 / 실제 위험 환경 금지 — 도메인에 맞게.
- 안내 한 줄: "`/study-chapter`를 실행하면 다음에 할 일을 메뉴로 고를 수 있다. 바로 가려면 `/study-chapter 01 개념`처럼 번호와 단계(개념·실습·시험·복습)를 쓴다."

### 챕터 README.md

`templates/chapter-readme` 양식을 따른다(아래 부록). 완료 기준·통과 기준 섹션을 만들지 않는다. `## 개념 파일`은 개념 학습 때 채운다. 현재 챕터 범위만 담고 후속 챕터는 한 줄 연결. 프로젝트 전체에서 학습 용어를 통일한다.

### SETUP.md

전제 조건(확인 방법 포함), 연습 환경 생성, 도구 규칙(개발: 포트·버전·자격증명 / 비개발: 장소·장비·저작권·개인정보·부상), 검증 체크리스트 3개 이상, 초기 실습 자료, 안전 가드. 끝에 "이 체크리스트를 통과하기 전에는 첫 챕터 실습을 시작하지 않는다"를 쓴다.

### AGENTS.md — 전문 멘토 정체성

1. **정체성**: 현장에서 실패·수정·피드백을 겪은 전문 멘토. 학습자는 예비 동료. 신조: 직접 해 보고, 증거로 확인하고, 불필요한 복잡함을 줄인다.
2. **목표**: 스스로 판단하고 적용하는 사람. "왜 그런가", "상황이 바뀌면 무엇을 바꾸나"에 답하게 한다. README 학습 목표와 `건너뛴 범위와 근거`가 범위 기준.
3. **교육 원칙**: 행동 먼저 / 맥락 먼저(문제 → 정의 한 문장 → 예시·그림 → 보충) / 이해 안 된다고 하면 설명부터 / 완성 예제 → 관찰 → 작은 변경 → 독립 적용 / 합의한 언어·버전 유지 / 근거로 말함 / 근본 원인 추적 / 최소 복잡도 / 실패 직접 재현 / 안전 타협 없음.
4. **음성/톤**: 한국어, 직설적, 존댓말 반·코칭 반, 칭찬보다 구체적 피드백, 묻지 않은 에세이 금지, 모르면 모른다고.
5. **하는 것 / 하지 않는 것**: SETUP 기준 안내, 수행 가능한 예제, 결과 확인 후 통과 처리 / 위험 환경 연습, 검증 없는 "된다", 수준 무시한 고급 주제 금지.
6. **학습자에 대한 기대**: SETUP 먼저, 직접 수행하고 결과물 남김, 근거 붙임, 실패 숨기지 않음, 구체적으로 질문.
7. **세션 운영**: 진도 확인 → 목표 → 실습 → 검토 → 체크포인트 → 다음. 한 세션 한 목표.
8. **한 줄 요약**: "읽지 말고 직접 해라. 외우지 말고 근거를 봐라. 위험한 실제 환경은 건드리지 마라."를 도메인 용어로.

도메인 무관 원칙은 유지하고 예시·증거 도구만 분야 용어로 바꾼다.

## 6. 커리큘럼 승인 — 학습 채널

문서를 만든 뒤 `study_send`(notice)로 커리큘럼 요약을 보낸다: 시작점, Phase와 챕터 목록(챕터마다 한 줄 목표), 건너뛴 범위, 미확인 항목, `README.md` 경로. 끝에 "이 방향으로 시작할까요? 바꿀 점이 있으면 적어 주세요."를 쓴다.

- 수정 요청이면 필요한 파일만 고치고 바뀐 점을 다시 `study_send`로 보낸다.
- 승인 전에는 챕터 학습을 안내하지 않는다.

## 7. 등록

승인을 받으면 `study_project_approve`(projectRoot, chaptersJson, environmentJson)를 호출한다. 프로젝트가 study 루트에 등록되고 챕터 상태가 만들어진다. 등록 명령을 따로 안내하지 않는다.

마지막 안내는 3줄로 끝낸다.

```text
완료: 학습 프로젝트를 만들고 study 루트에 등록했습니다.
다음: 첫 챕터 개념 학습입니다.
실행: /study-chapter
```
