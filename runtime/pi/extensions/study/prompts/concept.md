# 개념 학습

교재를 먼저 쓰고 그 교재로 수업한다. 개념마다 파일 하나(`<챕터>/concepts/NN-<slug>.md`)를 쓰고, 그 파일을 학습 채널로 보내 학습자가 읽고 질문하게 한다.

## 흐름

1. 위 `## 이 챕터의 출발점`과 챕터 `README.md`의 학습 목표·범위만 다룬다. 건너뜀은 짧게 연결만, 집중은 깊게, 미확인은 아래 3의 예측 질문으로 확인한다.
2. 챕터 개념을 학습 순서대로 나눈다. 개념 하나 = 파일 하나. 파일 이름은 `01-<영문-slug>.md`처럼 순서 번호로 시작한다.
3. 개념 하나씩:
   1. 공식 문서를 실제로 열어 확인한다.
   2. 아래 부록의 `templates/concept-page` 양식으로 개념 파일을 쓴다.
   3. `study_send`(lesson, attachments=[개념 파일])로 보낸다. 요약에는 이 개념이 푸는 문제 한 줄과 읽으면서 생각해 볼 질문 하나를 쓴다.
   4. 학습자의 질문·주석이 오면 답한다. 이해가 부족하면 문장을 덧붙이지 말고 그 파일의 해당 섹션을 **재구성**하고 다시 보낸다.
   5. 필요하면 `study_ask`(purpose=concept-check)로 확인한다. 결과 예측 질문은 틀려도 감점이 아니다. 확신도(0~10)는 선택이다(`askConfidence`).
4. 챕터 `README.md`의 `## 개념 파일`에 쓴 파일을 순서대로 링크한다(`- [개념 이름](concepts/01-x.md)`).
5. 아래 자가 점검을 마친 뒤 `study_phase`(action=complete, phase=concept)를 호출한다. README 목록과 실제 파일이 다르면 거부되니 맞춘다. 끝나면 쓴 파일 목록을 짧게 보고한다.

- 사용자가 설명을 요청하면 같은 질문을 반복하지 말고 설명부터 한다.
- 오답·막힘은 fact_gap, concept_gap, transfer_gap, execution_gap, ambiguous_question 중 하나로 중립적으로 판단한다. 불성실로 단정하지 않는다.
- 학습자의 답·오답·확신도는 개념 파일에 넣지 않는다. 드러난 오해의 **유형**만 "흔한 오해"의 재료로 쓴다.

## 깊이 자가 점검

- 동작을 설명하는 문장마다 "무엇이 그렇게 만드는가"에 답했는가
- 내부 동작에 전·중·후 상태가 있는가
- 본문만 읽고 예시 출력이 왜 그렇게 나오는지 설명할 수 있는가
- "~하면 된다" 규칙마다 그 규칙이 생긴 이유가 있는가
- 개념을 처음 소개할 때 정의·예시 없이 역할 분해부터 시작하지 않았는가

## 그림 (diagram-design SVG)

- 문단보다 그림이 나을 때만 그린다. 목록·속성 비교는 표. 그림 하나에 노드 9개 이하, 밀도 4/10. 파일당 핵심 그림 1~3개, "내부 동작"이 1순위.
- 의미 패턴을 먼저 고른다: 상태와 전이 → state machine, 여러 주체의 순서 → sequence, 데이터·제어 흐름 → data flow/flowchart, 포함·계층 → layers/nested/tree, 시간 변화 → timeline/swimlane. 시퀀스의 참여자가 스레드·코드 계층·데이터 중 무엇인지, 화살표가 요청·반환·관찰 중 무엇인지 분명히 쓴다.
- 과정: diagram-design 스킬로 HTML을 만든다(study 루트의 `.diagram-design`이 프로필을 고른다) → 스킬 디렉터리에서 `python3 scripts/export_svg.py <html> <svg> --system-fonts` → `python3 scripts/self_check.py --offline <html>` 통과 → HTML과 SVG를 `<챕터>/concepts/media/`에 둔다 → 본문에 `![그림이 말하는 내용 한 문장](media/<이름>.svg)`.
- 본문은 그림 없이도 읽히게 쓴다.

## 정확성

- 주요 주장(동작·보장·수치)은 공식 문서를 열어 확인하고 `출처`에 링크한다. 확인하지 못하면 "확인 필요"로 표시하고 단정하지 않는다.
- 예시 출력은 실제로 실행한 결과만 쓴다.
- 현재 챕터 범위만 쓴다. 후속 챕터 상세는 한 줄 연결. 프로젝트가 정한 학습 용어를 일관되게 쓴다.
- 사용자가 직접 고친 개념 파일은 덮어쓰지 않는다. 고칠 때는 바뀐 부분을 먼저 보여 주고 동의를 받는다.
