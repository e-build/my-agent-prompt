# 기존 study review와 연결

## 먼저: 통합 복습인지 기존 방식인지

- study 루트 최상위에 `.study/workspace.json`이 있고 프로젝트가 그 안에 등록돼 있으면 **통합 복습**이다. 일정 정본은 루트 `review/items/<지식 ID>.json`(지식마다 하나), 원 응답은 루트 `review/sessions/`다. 챕터 `review/schedule.md`를 새로 만들거나 고치지 않는다.
- 통합 복습 규칙: 간격 +1 / +3 / +7 / +14일, 기준일은 챕터를 끝낸 날, 다음 날짜는 실제 복습한 날부터. 틀리거나(부분 정답 포함) 힌트 후 맞히면 그 지식만 처음 간격부터 다시(“힌트 후 정답”으로 따로 기록). 마지막 회차 후 종료, 하루 양 제한 없음, 미래 회차는 미리 하지 않음. 다른 챕터에서 다시 나왔다는 이유만으로 일정을 옮기거나 완료하지 않는다.
- Pi의 `study_review_next`·`study_question_prepare`·`study_answer_record`를 쓸 수 있으면 사용한다: 질문 전 기준 저장 → 공개 질문 → 원 응답과 지식별 판정 기록. 도구가 일정을 계산하므로 날짜를 직접 고치지 않는다.
- 도구를 쓸 수 없는 환경에서는 통합 복습 파일을 직접 편집하지 않는다. 대화 메모만 남기고 Pi에서 기록이 필요함을 보고한다. 자유 대화를 회차 완료로 바꾸지 않는다.
- 등록되지 않은 프로젝트는 아래 기존 방식(챕터 schedule.md)을 따른다. 두 방식을 섞지 않는다.

## 기존 방식 — 미등록 프로젝트

챕터 README가 교재 정본, review/schedule.md가 일정과 핵심 개념의 정본이다. review/README.md는 정답을 공개하지 않는 시작 페이지다. 교재나 오답 본문을 복사한 study-pack을 만들지 않는다.

### 회차 선택과 인정

- 기존 schedule.md에서 아직 완료되지 않은 기한 경과 회차를 우선하고, 없으면 오늘 회차를 확인한다. 사용자가 특정 회차를 지정했다면 그 회차의 실제 일정과 기존 기록을 확인한다.
- 미래 회차를 당겨 수행한 지연 복습으로 처리하거나 일정이 없는 곳에 R1을 자동 생성하지 않는다. 간격, 기준일, 시간대, 핵심 개념의 신규 설정은 별도 합의가 필요하다. 설정 없이도 챕터 대화는 진행한다.
- 자유 대화도 실제로 기존 회차의 핵심 개념들을 기억에서 설명하고 필요한 보충/교정 확인을 수행했다면 그 회차의 근거로 사용할 수 있다. 회차 연결을 위해 첫 답변을 받기 전에 정답을 보여주지 않는다.
- 완료는 해당 회차의 합의된 핵심 개념을 실제로 다루고, 중요한 오개념을 확인·보완했는지로 판단한다. STRONG만 있어야 완료되는 것은 아니지만 미해결 핵심 개념이 남으면 부분 수행이다. 보충 성공은 독립 회상 성공과 구분한다.
- 큰 챕터의 일부 묶음만 다룬 대화는 전체 핵심 개념을 다룬 회차로 처리하지 않는다. 미진행/건너뛴 개념을 명시한다. 직접 실행을 요구하는 작업은 대화 회차의 필수 조건으로 추가하지 않는다.
- 본 학습 중이거나 학습 직후라면 그 사실을 기록한다. 실습·시험 완료를 추측하거나 대화만으로 완료 상태를 바꾸지 않는다. 최근 교재 열람이나 설명 제공 여부는 알려진 근거로 기록하고, 판정에 필요한 정보가 불명확하면 짧게 확인한다.
- 같은 날 여러 대화를 밀린 복습 회차 여러 개로 완료하지 않는다. 완료 회차를 다시 수행한 대화는 추가 기록이며 완료 수를 늘리지 않는다. STRONG 개념도 이후 회차의 반복 대상이다.

### 기록 파일

대상 회차가 있으면 기존 기록 링크를 사용한다. 아직 링크가 없다면 review/sessions/rN.md에 기록한다. 기존 파일은 덮어쓰지 않고 대화별 구역을 추가한다.

회차가 없거나 미래 회차뿐이면 review/sessions/dialogue-YYYY-MM-DD-NN.md로 일반 대화 기록을 남긴다. NN은 같은 날 기존 파일을 확인해 충돌 없이 정한다. 날짜와 시각은 사용자의 시간대로 기록한다. 불명확한 시간대는 환경 맥락을 확인하며 추측으로 복습 일정을 바꾸지 않는다.

#### 기본: 다음 대화를 위한 짧은 메모

일반 대화는 다음 질문을 선택하는 데 필요한 내용만 남긴다. 날짜·챕터·진행 범위와 회차 미연결 사유를 짧게 적고, 아래 항목을 몇 줄로 정리한다.

- 스스로 설명한 개념이나 관계.
- 도움받은 부분과 이후 이해 확인 여부.
- 다음에 확인할 구체적인 관계나 질문. 단순히 생략한 내용은 이해 부족으로 기록하지 않는다.

질문·답변 전문, 발언별 판정, 생성/종료 시각 등의 상세 이력은 기본 기록에 넣지 않는다. 도움이 됐는지 판단할 수 있는 짧은 응답 요지는 필요한 경우에만 추가한다. 다음 대화에서 최근 메모의 확인 항목을 실제 질문에 반영하고, 해결됐으면 새 메모에 그 결과를 남긴다. 이미 설명한 내용의 확인 질문은 줄이되 정식 복습 회차의 반복 범위는 유지한다.

#### 정식 review 회차 연결: 판정에 필요한 근거 추가

기존 회차에 연결하는 대화는 다음 정보를 추가한다. 부분 수행도 해당한다. 간결한 개념별 응답 요지로 근거를 남기며 전체 대화를 전사하지 않는다.

- 대상 회차, 예정일/실제 수행일과 시간대, 알려진 입력 방식, 최근 교재 열람/보충 여부 또는 미확인.
- 핵심 개념 ID/이름과 교재 위치, 질문의 요지, 최초 응답의 정확한 요지와 판정 근거.
- 제공한 힌트/설명의 요지, 이후 응답과 판정. 독립 회상과 교정 직후 답변을 구분.
- 미해결/미진행 항목과 회차 완료 또는 부분 수행의 근거.

기존 상세 회차 기록은 덮어쓰지 않는다. 일반 대화 메모를 나중에 회차 근거로 사용할 때, 남아 있지 않은 질문이나 원 답변을 지어내지 않는다. 근거가 부족하면 필요한 개념을 다시 확인한다.

필요한 경우 기존 review의 STRONG/WEAK/WRONG 표지를 기록에 사용할 수 있다. 사용자에게는 점수 없이 구체적인 피드백을 준다. STRONG은 이번 대화에서 보충 불필요라는 의미이며 장기 기억 정착 인증이 아니다. 미진행 개념에 WRONG을 부여하지 않는다.

### 일정과 상태 동기화

1. 실제 대화 기록을 먼저 저장하고 파일 내용을 확인한다. 동일 대화를 재저장할 때 기존 구역을 확인해 중복 추가하지 않는다.
2. 기존 회차에 연결한 경우에만 schedule.md의 해당 행을 갱신한다. 부분 수행은 in_progress, 완료는 completed로 기록한다. 실제 수행일과 기록 링크를 넣고, 예정일·다른 행·핵심 개념 목록은 보존한다. 기존 회차 기록 링크가 있으면 그대로 사용한다.
3. 다음 표 형식을 유지한다. 기록 셀은 Markdown 링크 문법이 아닌 상대 파일 경로다. 일반 대화는 고정 회차 표에 새 행을 추가하지 않는다.

   ```markdown
   ## 고정 회차

   | 회차 | 예정일 | 상태 | 실제 수행일 | 기록 |
   |---|---|---|---|---|
   | R1 | 2026-10-13 | completed | 2026-10-13 | sessions/r1.md |
   ```

   위 날짜는 형식 예시이며 실제 기록에는 확인한 일정/수행일을 사용한다.

4. 모든 합의된 회차의 실제 기록과 완료를 확인하고 사용자가 주기 완료를 명시한 경우에만 `- 주기 상태: completed`로 기록한다. 일부 수행/다음 회차 대기는 in_progress다. 완료 선언이 없으면 마지막 회차 완료와 주기 완료 확인 대기를 구분한다. 일정 미설정 상태는 일반 대화로 변경하지 않는다.
5. `study_review_refresh`가 제공되면 지정한 프로젝트/챕터를 갱신한다. 도구가 없으면 파일 접근으로 아래 최소 동기화를 수행한다. 다른 환경에서 Pi 도구를 호출할 수 있다고 가정하지 않는다.

#### Pi 갱신 도구가 없는 환경

- `.study/state.json`이 유효한 version 1 형식이고 대상 챕터가 있으면 해당 챕터의 review 상태만 schedule 원본과 실제 기록에 맞춘다. 일정 미설정은 not_started, 일정 설정/일부 수행은 in_progress, 명시적 주기 완료와 모든 회차 기록이 확인되면 completed다. review.updatedAt과 루트 updatedAt은 실제 갱신 시각으로 변경한다.
- activeChapter, activePhase, 다른 phase, 다른 챕터와 기존 필드는 보존한다. 신규 상태 파일 생성, 레거시 마이그레이션, 모르는 버전의 임의 수정은 하지 않는다. JSON 저장 전후로 파싱하고 변경 대상 외의 값이 보존됐는지 확인한다.
- 기존 review/README.md에 `<!-- study-review-navigation:start -->`와 `<!-- study-review-navigation:end -->` 관리 구역이 있으면 그 안의 현재 위치와 회차 기록 링크를 일정에 맞춰 갱신한다. 개념 이름/원문 링크만 공개하고 사용자 답변·교정 내용은 세션 파일에 둔다. 관리 구역 밖 메모는 보존한다.
- 페이지가 없거나 관리 마커/일정 구조가 불명확하면 자동으로 덮어쓰거나 새 시작 페이지 형식을 만들지 않는다. 실제 기록을 보존하고 Pi에서 시작 페이지/상태 갱신이 필요함을 보고한다. 상태 파일도 수정할 수 없는 형식이면 같은 원칙을 적용한다.

저장 직전에 대상 파일의 변경 여부를 다시 확인하고, 다른 대화의 기록이 추가됐다면 최신 내용을 기준으로 합친다. 파일 저장, 일정 갱신, 상태/시작 페이지 갱신 중 어디까지 성공했는지 구분해 보고한다. 실패한 저장을 성공으로 말하거나 다음 단계의 완료 근거로 삼지 않는다. Git 커밋·푸시 및 checkpoint 발행은 수행하지 않는다.
