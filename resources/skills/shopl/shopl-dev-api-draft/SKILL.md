## 목적과 산출물

- 독자: 클라이언트 개발자.
- 산출물: `docs/<feature>/api-draft.md`.
- 기본 형식: **API별 요청·응답 계약 변경 사항만 담은 간결한 문서**.
- 전체 구현 계획·정책 검토·코드 분석 보고서를 작성하는 스킬이 아님.
- 사용자가 전체 신규 API 설계를 명시적으로 요청한 경우에만 전체 계약 명세로 확장.
- 상세 규칙과 예시는 [REFERENCE.md](./REFERENCE.md) 참조.

## 포함 기준

- **요청 또는 응답 계약이 변경된 API만 포함**. 신규 API도 포함.
- 필드 추가·수정·삭제, 타입·필수 여부·enum·구조 변경 등 전송 계약 차이를 기준으로 판정.
- 내부 로직·계산·저장 방식·검증 구현만 바뀐 API는 제외.
- 기존 필드에 저장된 값이 달라졌다는 이유만으로 조회 API를 포함하지 않음.
- Excel 열·파서·DB 저장 처리만 변경되고 API 요청·응답 계약은 그대로면 제외. 파일 양식 변경 안내는 별도 문서로 분리.
- 연관 API, 영향 확인 대상, 기존 API 재사용 목록을 명세 분량에 추가하지 않음.
- **코드 변경 API 목록과 클라이언트 요청·응답 변경 목록을 혼동하지 않음**.
- 삭제 API가 있으면 method·path와 삭제 사실만 기재. 이미 삭제된 요청·응답을 다시 명세하지 않음.

## 작성 절차

1. 프로젝트 `AGENTS.md`와 관련 API convention 확인.
2. 구현 분해·정책 근거와 기존 Controller·DTO·Mapper를 비교해 요청·응답 차이 식별.
3. 구현 후 문서라면 실제 diff/코드를 기준으로 작성. 구현 전이라면 합의된 계약만 작성하고 초안임을 짧게 표시.
4. 미확정 필드·경로·enum·오류 코드를 확정 명세처럼 작성하지 않음. 내부 검토 기록으로 분리.
5. 포함 기준에 해당하지 않는 API는 제거한 뒤, API마다 `요청`·`응답`으로 구분.
6. 변경된 내용만 짧게 설명하고 필요한 JSON 예시 작성.
7. 기존 문서를 축약할 때 상세 기록 보존이 필요하면 `api-design-notes.md`로 분리하고 참조 링크/앵커 정합성 확인.

## 출력 형식

API마다 아래 순서 유지. DTO 클래스명·구현 클래스명은 노출하지 않음.

````md
## 1. 정책 요약 조회

`GET /admin/example/{id}`

### 요청

변경 없음.

### 응답

`hasFixedAmountCommission` 추가 — Boolean, 항상 포함.

- `true`: 고정 금액 커미션 포함.
- `false`: 고정 금액 커미션 없음.

```json
{
  "hasFixedAmountCommission": true
}
```
````

- 헤더는 **`요청`, `응답`**만 사용. `응답 필드 추가`, `응답 추가 필드만 발췌` 같은 헤더·도입 문구 금지.
- 변경 없는 쪽은 **`변경 없음.` 한 줄**. 기존 필드·body·권한·페이징을 재설명하지 않음.
- 변경된 쪽은 `필드명 + 추가/수정/삭제 + 필요한 타입·필수 여부·의미`만 기재.
- JSON은 주석·생략 기호·pseudo-class 없는 유효한 형식. 설명은 JSON 밖에 작성.
- 기존 API 예시는 변경 필드와 위치를 보여주는 최소 구조만 포함. 변경 없는 전체 body 반복 금지.
- 변경된 필드가 없으면 해당 쪽의 JSON 예시도 생략.
- 신규 API는 기존 계약이 없으므로 필요한 요청·응답 전체 명세. path/query/multipart를 JSON body로 표현하지 않음.

## 검증

- [ ] 모든 API에 실제 또는 합의된 요청·응답 계약 변경 근거가 있는가?
- [ ] 내부 처리·Excel·저장 변경뿐인 API와 연관 조회 API를 제외했는가?
- [ ] API별 `요청`·`응답` 아래 변경 여부와 내용만 정리했는가?
- [ ] 변경 없는 쪽은 `변경 없음.`만 적고 예시는 제거했는가?
- [ ] JSON이 그대로 파싱되며 필드명·타입·enum·필수 여부가 실제 계약과 일치하는가?
- [ ] 미확정 후보·내부 task/Q-ID·구현 설명이 클라이언트 문서에 섞이지 않았는가?
- [ ] 문서 링크/앵커가 유효하며 기존 상세 기록의 참조가 끊기지 않았는가?
