# zz-workflow:continue

기존 기능의 작업을 이어서 진행한다. 상태 문서 3종을 진단해 현재 위치를 요약하고, 승인된 작업을 수행하며, 확정 시 상태 문서를 동시에 갱신한다.

## 사용법

```
/zz-workflow:continue [$FEATURE_NAME]
```

- `$FEATURE_NAME`: 이어서 진행할 기능 식별자 (`docs/features/` 하위 디렉토리명). 생략 시 진행 중인 기능이 하나뿐이면 자동 선택, 여러 개면 선택 질문.

## 역할 구분

| 상황 | 사용 명령 |
|---|---|
| 새 기능 또는 새 버전 디렉토리 생성 | `/zz-workflow:new` |
| 기존 기능·버전의 작업 재개 | `/zz-workflow:continue` (이 명령) |

## 상태 문서 3종

이 명령이 진단·갱신하는 단일 진실 공급원. 다른 문서는 단계 작업 중 필요할 때만 읽는다.

1. `PROGRESS.md` (루트) — 기능별 매트릭스, 현재 요약, 다음 진행 흐름
2. `docs/features/{name}/v{version}/index.md` — 문서 맵 상태
3. `docs/features/{name}/v{version}/07-progress.md` — 단계별 체크리스트, TODO, 블로커

---

## 실행 절차

### Phase 1: 상태 진단

1. **init 확인** — 루트에 `AGENTS.md`와 `PROGRESS.md`가 없으면 "먼저 `/zz-workflow:init`을 실행하세요" 안내 후 중단.
2. **기능 확정** — `$FEATURE_NAME`을 `docs/features/` 하위 디렉토리 목록과 대조해 확정. 없으면 목록을 보여주고 선택 질문.
3. **버전 확정** — `docs/features/{name}/` 하위에서 최근 버전 디렉토리를 기본으로 선택. 여러 개면 선택 질문.
4. **상태 수집** — 아래 항목만 읽는다 (이 시점에 다른 문서를 미리 읽지 않는다):
   - `PROGRESS.md`: 해당 기능 매트릭스 행, "현재 요약", "다음 진행 흐름" 섹션
   - 기능 `index.md`: 문서 맵 (작성 예정/초안/확정)
   - `07-progress.md`: 마지막 기록, 미완료 TODO, 블로커
   - `06-decisions.md`: 마지막 D번호와 제목만
5. **현재 단계 판정** — index 문서 맵과 07-progress를 교차 확인해 1~6단계 중 현재 단계를 결정. **두 문서가 불일치하면** 불일치 내용을 보고하고 사용자 판단을 구한다.

### Phase 2: 요약 보고 (게이트)

진단 결과를 아래 형식으로 출력하고 사용자 확인을 받는다. 확인 없이 단계 작업을 시작하지 않는다.

> ```
> {Feature Name} v{version} — 현재 상태
> • 현재 단계: {N}단계 ({단계명}) — {진행 상태}
> • 완료: {확정된 단계·산출물 요약}
> • 진행 중/미결정: {오픈포인트, 미승인 항목}
> • 블로커: {있으면 표기, 없으면 "없음"}
> • 다음 작업: {현재 단계 내 가장 작은 실행 단위 1가지}
> • 먼저 읽을 문서: {현재 단계 문서 경로}
> ```

### Phase 3: 단계 작업

1. 사용자가 승인한 다음 작업 1가지를 수행한다. 한 번에 여러 단계를 건너뛰지 않는다.
2. AGENTS.md의 해당 단계 절차와 "단계별 체크리스트"를 따른다.
3. 결정이 발생하면 기존대로 `06-decisions.md` 포맷(일자·결정·채택/기각 사유·근거·영향 문서)으로 기록한다.
4. 리뷰가 필요하면 문서에 리뷰 확인 포인트를 남기고, 기존 리뷰 흐름(Plannotator 등)을 안내한다.
5. 세션 중단이 필요하면 기존 `handoff` 스킬을 사용한다.

### Phase 4: 상태 동기화 (산출물 확정 시)

사용자가 산출물을 승인하면 부분 갱신 없이 아래 3개 문서를 함께 갱신한다:

1. `07-progress.md` — 해당 항목 체크, 완료 기록, 남은 TODO 갱신
2. 기능 `index.md` — 문서 맵 상태를 실제 상태(초안/확정)로 변경
3. `PROGRESS.md` — 매트릭스 해당 셀 갱신. "현재 요약"·"다음 진행 흐름" 섹션이 실상과 달라지면 함께 갱신

동기화 직후 아래를 교차 확인해 보고한다:

- 매트릭스 행 ↔ index 문서 맵 상태 일치
- 07-progress에 존재하지 않는 파일을 참조하는 항목 없음
- 다음 작업 안내가 "다음 진행 흐름"과 모순되지 않음

이후 다음 단계 진입 여부를 질문하고, 진입 시 AGENTS.md의 해당 단계 "시작 전" 체크리스트를 먼저 검증한다.

---

## 출력 예시

```
/zz-workflow:continue engagement

→ engagement v1 — 4단계 (API 명세) 진행 중
→ 다음 작업: 04-api.md 리뷰 확인 포인트 2건 처리
→ (작업 수행 → 사용자 승인)
→ 07-progress + index + PROGRESS 동기화 완료 (매트릭스 ✓·문서 맵 ✓)
→ 다음: 4단계 잔여 항목 확정 후 5단계 시작 전 체크리스트 검증
```

## 주의

- 이 명령은 상태 진단·단계 진행·상태 동기화에 한정한다. 게이트 통과 판단은 항상 사용자 승인으로만 이루어진다.
- 기능의 요구사항·정책 자체가 바뀌는 대규모 변경은 `/zz-workflow:new`로 새 버전 디렉토리를 만들어 진행한다.
