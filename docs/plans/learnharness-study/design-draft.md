## 문서 상태

- **목적:** 사용자 선택을 하나의 설계로 연결하고 남은 세부 계약 검토
- **상태:** 학습 흐름 요약·LearnHarness 도입 6개 원칙 확인 완료. 복습 간격·레거시 이전·저장/복구 등 세부 계약 검토 진행 중. 확인 범위 밖의 `제안`을 사용자 승인으로 간주하지 않음
- **변경 범위:** `my-agent-prompt/docs/plans/learnharness-study/`의 설계 문서만 변경. 실제 study 저장소·extension 코드·기존 학습 자료는 미변경
- **실행 단계:** 브레인스토밍. 구현·폴더 생성/이동·마이그레이션·커밋·푸시 진행 없음
- [사용자 결정과 근거](decisions.md), [저장소 구조 상세](workspace-design.md), [그래프 예시](knowledge-graph.html), [초기 조사](research.md) 참고
- LearnHarness에서는 역할·상호작용 아이디어를 참고. 소스·프롬프트 복사나 파생 구현을 전제로 하지 않음

## 확정한 방향

| 영역 | 사용자 선택 |
|---|---|
| 전체 흐름 | 진단 → 개념 학습 → 프로젝트 실습 → 완료 테스트 → 지연 복습 |
| 진단·수업 | Pi에서 대화하며 이해 수준에 따라 조절 |
| 실습 | 예제 분석·기존 코드 변형·독립 구현 등의 도움 방식을 에이전트가 과제별로 선택 |
| 완료 테스트 | 기존 HTML 시험 유지 |
| 지식 | 명제를 저장·재사용의 기본 단위로 중앙 관리. 큰 개념은 이름·태그·목록으로 탐색, 여러 프로젝트는 자기 맥락에서 같은 지식 참조 |
| 관계 | 공동 전제 → 결론, 목표별 선수 학습, 프로젝트 적용 맥락을 구분. 공동 전제 묶음과 독립 논증 보존 |
| 수집·사용 | 자료·교재·교사 설명에서 후보 수집, 근거·조건 확인. 미확정은 보존하되 확정 교재·정답 기준으로의 사용 보류. 학습자 답변은 수행 근거로 분리 |
| 반영 | 자동 반영 후 사후 검토. 보수적 병합, 표현 추가·내용 교정·별도 주장 구분, 버전·과거 답안 연결 보존 |
| 교재 | 공통 설명을 README 본문에 포함하고 관리 영역 자동 최신화. 명제 목록이 아니라 설명·예시·맥락을 묶은 교재 |
| 복습 | 명제별 통합 일정, 프로젝트·챕터는 범위 필터. 질문은 묶어 구성하되 실제 확인한 범위에만 수행 근거 연결 |
| 저장소 | 하나의 study 루트에서 전체 관리. PC별 절대 경로는 달라도 됨 |
| 배치 | 기존 `study-*` 위치 유지. 루트에 `.study/`·`knowledge/`·`review/` 추가 |
| 화면 | 작은 Pi 상태 위젯 + 필요할 때 지도 열기. 우측 고정 패널 제외 |
| 제외 | 새 음성 인식·모델/계정/비용 관리, 별도 학습 SaaS, 프로젝트 폴더 이동 |

## 설계 1 — 학습 경험과 단계

**상태: 학습 흐름 요약 사용자 확인 완료. 경로 결정 중심 진단·기본 8문항 상한·유연한 설명/예측/확인·개념 후 실습·HTML 시험 확정. 아래 저장·재개 등 세부 계약은 구현 설계 제안.**

### 입력과 커리큘럼

- 주제 문자열, 사용자 지정 파일·디렉터리·URL을 입력으로 수용
- 접근한 자료와 접근하지 못한 자료를 구분하고 자료 범위·버전·시점을 남김
- 목표·자료·기존 지식의 관계를 조사해 주제별 커리큘럼 생성. 공통 지식이 있다고 학습 완료로 취급하지 않음
- 기존 브리프 확인과 커리큘럼 브라우저 미리보기 유지. 승인 전 챕터 학습 진입 금지
- 동일 지식은 재사용하되, 이 주제에서 요구하는 설명·판단·수행의 맥락은 별도 명시

### 대화형 진단 — 학습 경로를 고를 만큼만

1. 챕터 목표와 관련된 기존 학습 근거 확인. 자료 열람·도움 여부·시점·적용 조건을 함께 검토
2. 대표 상황으로 한 번에 하나씩 질문. 객관식과 자유 응답을 목적에 맞게 선택
3. 답에 따라 필수 선수 지식을 확인하거나 더 높은 수준의 설명·판단으로 이동
4. 다음 학습 경로를 결정할 수 있으면 종료. 모르는 모든 가지를 끝까지 탐색하지 않음
5. 확인된 부분·미확인 부분·시작 지식·추천 깊이를 요약한 뒤 개념 학습으로 이동

운영 제안:

- 대표 상황부터 질문하고 **진단 질문 상한 기본 8개** 적용. 고정 최소 문항 수가 아니며 일찍 종료 가능. 수치는 합의한 운영 기본값이며 교육학적 최적값 주장 아님
- 상한은 해당 진단 시도의 실제 출제 수로 관리. Pi 세션을 바꾸거나 중단 후 재개해도 초기화하지 않음. 질문 재전송은 새 출제로 세지 않지만 내용이 바뀐 재출제는 별도 질문으로 기록
- 상한 도달 시 미확인을 명시한 보수적 학습 경로 제안. 임의 통과·실패 판정이나 재귀적 추가 진단 금지
- 사용자의 설명 요청·중단·건너뛰기 허용. 답을 못 했다는 이유로 설명을 보류하지 않음
- 진단 종료는 경로 결정/상한/사용자 요청 등의 사유와 함께 기록. `진단 종료`와 `모든 지식 이해`를 구분
- 최근의 관련 독립 수행 근거가 충분하면 반복 확인 축소. 지식 존재·자기보고·교사 설명만으로 확인 완료 처리 금지

### 개념 학습 — 설명·예측·확인의 짧은 루프

기본 루프 제안:

```text
이번 지식이 풀 문제와 짧은 설명
→ 필요할 때 결과 예측
→ 예시·원리·조건 설명
→ 자기 말 설명 또는 조건을 바꾼 이해 확인
→ 필요한 부분만 보충하거나 다음 지식으로 이동
```

- 예측은 설명 전에 현재 생각을 드러내는 활동. 미학습 내용을 틀렸다고 숙련도 감점하지 않음
- 확인은 설명 후 의미·관계·적용 조건을 사용할 수 있는지 살펴보는 활동
- 모든 문장 뒤에 질문 강제 금지. 설명을 요청하면 먼저 설명하고 필요할 때 확인
- 이유를 묻되 장문 사고 과정 제출 강제 금지. 학습자가 실제로 말하거나 쓴 근거만 기록
- 자기보고 확신도는 선택적으로 수집. 정확성·독립 수행·장기 기억과 구분
- 오답 원인을 사실·개념·전이·실행·문항 모호성으로 구분해 필요한 도움 선택
- 새 범위를 발견하면 현재 챕터를 무한 확장하지 않고 후속 학습 대상으로 분리
- 개념 학습을 마친 뒤 프로젝트 실습 시작. 개념 중 예측·짧은 확인을 프로젝트 실습 단계로 간주하지 않음
- README는 채팅 복사본이 아니라 공통 설명과 해당 챕터 맥락으로 재구성된 교재

### 실습 — 도움 수준과 실행 성공을 별도로 기록

| 상황 | 도움 방식 제안 | 확인할 근거 |
|---|---|---|
| 새 개념·낯선 도구, 실행 구조 자체가 어려움 | 완성 예제 분석·실행 | 결과 관찰, 각 요소의 역할 설명 |
| 기본 원리는 알지만 조건 변화 적용이 어려움 | 기존 예제의 작은 수정 | 수정 예측, 실제 변화, 이유 |
| 필요한 토대와 관련 수행 근거가 있음 | 독립 구현·문제 해결 | 독립 시도, 산출물, 검증, 설명 |

- 에이전트가 선택 이유를 짧게 밝히고 필요에 따라 도움 수준 조절. 사용자 변경 가능
- 예제 분석 → 수정 → 독립 구현을 모든 step에서 의무적으로 전부 수행하지 않음
- `lab.mode`의 cli/application/document/mixed는 **산출물·환경 유형**. 위 **도움 방식**과 다른 축으로 유지
- 실제 preflight·manifest·검증 명령·측정 테스트 수·산출물 검증 유지
- `study_lab_verify` 전 학습자가 직접 관찰한 결과와 배운 점을 받아야 함. 에이전트가 대신 작성한 설명으로 대체 금지
- 실행 성공, 학습자 설명, 에이전트 도움 여부를 분리. 에이전트 작성 코드의 통과를 독립 구현 성공으로 기록하지 않음

### 완료 테스트와 지연 복습

- 완료 테스트는 기존 `study_test_open`의 HTML 제출·채점·결과 확인 흐름 유지
- 현재 챕터에서 배운 범위의 변형 문제 출제. 통과·결과 확인·필수 학습 근거 검증 후 완료
- 미달이면 부족한 부분만 보완하고 새 attempt로 평가. 전체 챕터 반복 금지
- 지연 복습은 루트의 통합 일정에서 별도 진행. 미래 회상을 오늘 몰아서 수행하거나, 복습 등록만으로 완료 처리하지 않음
- 다음 챕터 학습은 미래 복습 예정 때문에 차단하지 않음

### 진단 담당과 수업 담당의 경계

- 진단 담당: 현재 응답·기존 근거에서 확인 범위와 다음 학습 경로 제안
- 수업 담당: 해당 경로의 설명·예시·도움·연습 진행
- 평가 기준과 원 응답은 공동 근거로 사용하되, 교사가 설명한 내용을 학습자 응답으로 넘기지 않음
- **구현 제안:** 먼저 역할별 지침과 입출력 계약 분리. 별도 에이전트 프로세스·동시 실행·모델 분리는 필수 요건으로 추가하지 않음
- 역할 분리가 평가의 객관성을 보증하는 것은 아님. 원 응답·기준·판정 근거로 검토 가능하게 구성

## 설계 2 — 지식과 학습 근거

**상태: 명제 기본 단위·분해 수준·관계 의미·수집/사용 경계·동일성/교정·교재/복습 경험의 6개 도입 원칙은 사용자 확정. [원본 조사](learnharness-knowledge-model.md) 후 별도 선택으로 기존 개념/원칙 기본 노드 제안을 대체. 구체적 스키마·상태 전환·쓰기/복구 절차 등은 구현 설계 제안.**

### 기본 단위와 관계

확정한 기본 단위와 분해 수준:

- 명제를 저장·재사용의 기본 단위로 사용. 짧은 이름은 표시용이며 구체적인 주장·조건·범위가 동일성 판단의 기준
- 큰 개념은 우선 이름·태그·목록으로 탐색. 별도 Concept 원본 계층은 도입하지 않음
- 독립적으로 참조·검증·질문·수정할 필요가 있는 주장을 분리. 재사용할 정의·규칙·판단 기준도 논증 연결 유무와 별개로 명제로 보존
- 설명·예시까지 문장마다 노드로 나누지 않음. 풀이·비유·일회성 실행 결과는 관련 명제의 설명이나 프로젝트 기록에 보존
- 그림 2의 일반 원리·조건부 주장·설명/기록 분리 수준을 기준으로 사용. 개별 자료의 정확한 분해는 에이전트가 수행하며 세부 추출·검증 절차는 후속 설계

확정한 관계 의미:

- 명제 간 추론, 목표별 선수 학습, 프로젝트 적용 맥락을 구분. 지도에서는 필요에 따라 함께 탐색
- 추론은 전제 묶음 → 결론. 여러 전제가 함께 필요한 경우 독립적으로 충분한 두 화살표로 바꾸지 않으며, 같은 결론의 독립 논증은 별도 사슬로 보존
- 선수 관계는 목표·학습자에 맞는 학습 순서. 선수 학습을 건너뛰어도 논리적 전제가 사라지는 것은 아님. 학습 지점 하나는 여러 명제를 참조 가능
- 적용 관계는 활용 장소와 맥락이며 이해 완료의 증거가 아님. 실제 설명·적용 여부는 수행 근거로 별도 확인
- 저장 파일·화면 개수는 이 결정과 별개. 추론 검토 절차·관계 이력·추가 관계 종류·렌더링 세부는 후속 설계

### 수집·근거 확인·사용 경계

확정한 원칙:

- 사용자 지정 자료·학습 교재·교사 설명에서 명제 후보 추출. 개인 노트도 자료로 지정한 경우 수집 가능
- 출처·조건·범위를 확인하고 원문에 명시된 내용, 도출한 해석, 가설을 구분. 출처가 있다는 사실이나 자동 검토를 참의 보증으로 간주하지 않음
- 미확정 후보도 보존하되 확정 교재·정답 기준으로 사용하지 않음. 근거가 충분한 후보는 동일성 판단 후 반영·활용
- 학습자 답변은 기본적으로 수행 근거. 틀린 답도 원 응답으로 남기며 맞았다는 이유만으로 공통 지식에 자동 승격하지 않음
- 논증의 근거가 부족하면 사슬을 꾸며내지 않음. 추출·근거 확인·동일성·저장은 구분된 책임이며 별도 프로세스 수를 강제하지 않음
- 자동 반영 후 사후 검토 유지. 모든 후보를 사용자 사전 승인 대상으로 바꾸지 않음

### 최소 정보 계약

아래 구체적 필드·원본 배치·참조 형식은 구현 설계 제안. 도입 원칙 선택만으로 필수 스키마까지 확정한 것은 아님.

| 항목 | 포함할 정보 |
|---|---|
| 지식 | 안정 ID, 표시 이름, 구체적 주장, 설명, 적용 조건·범위, 예시/반례, 상태, 현재 버전 |
| 관계 | ID, 관계 종류, 대상 ID, 필요한 조건, 근거, 추론의 전제 묶음·결론 |
| 출처 | 자료 ID, URL/파일 참조, 문단·코드 위치, 버전·확인 시점, 주장과의 연결 |
| 활용 맥락 | 프로젝트·챕터 ID, 목표, 지역 예시 위치, 지식 ID·참조 버전 |
| 학습 근거 | 실제 질문·응답, 당시 기준, 힌트/교정, 평가 이유, 자기보고 확신, 수행 시점·맥락·지식 버전 |
| 학습 경로 | 현재 목표·지식, 다음 후보, 선택 이유, 변경 이력 |

- 학습 근거는 원 응답을 보존하고 교정·재평가를 추가 기록. 최초 응답 덮어쓰기 금지
- 지식의 존재는 기록된 내용이라는 뜻. 이해·기억의 영구 등급이나 확률 점수로 자동 변환하지 않음
- 확신도 미응답·도움 여부 불명·실행 미확인은 추측하지 않고 미확인으로 표시
- 사용자가 맞혔다고 지식 주장이 참이 되는 것도, 설명이 존재한다고 사용자가 이해한 것도 아님
- 중앙 지식은 개인 학습에 참고할 기준 내용이지 무오류의 공인 정답 저장소가 아님. 불확실·상충 자료를 표시

### 출제 전에 답안 확정

- 평가하는 질문은 사용자에게 제시하기 전에 정답·허용 대안·조건·채점 기준·근거 버전을 저장
- 비채점 선호·경험 질문은 정답을 억지로 만들지 않고 비채점으로 명시
- 공개 질문 데이터와 정답·평가 기준 데이터 분리. 답변 전 브라우저 payload·숨겨진 HTML·일반 지도/위젯에 정답 포함 금지
- 사용자 답변을 본 뒤 기준을 조용히 변경하지 않음. 문항 오류 발견 시 무효/정정 사유와 최초 기준을 보존하고 재출제 또는 명시적 재평가
- 로컬 사용자가 자신의 파일을 직접 열 수 없도록 막는 감독 시스템은 범위 밖. 의도하지 않은 정답 노출을 막는 계약

## 설계 3 — 자동 반영과 단권화

**상태: 자동 반영·보수적 동일성 판단·교정 버전/과거 답안 보존·묶음 교재/본문 최신화는 확정. 트랜잭션·반영 시점·편집 충돌 복구의 세부 계약은 제안.**

반영 절차 제안:

1. 지정 자료·교재·교사 설명에서 후보 구성 후 근거 상태 확인. 학습자 답변은 별도 수행 근거로 보존
2. 기존 ID·설명·조건·범위·출처를 비교해 재사용/추가/수정/병합 선택
3. ID·관계·참조와 예상 기존 버전을 검증하고 변경 전후·이유·근거를 보존
4. 중앙 지식에 반영. 파괴적 제거 대신 이전 ID와 이력의 추적 가능성 유지
5. 영향을 받는 교재의 관리 영역 갱신, 그래프/복습 연결 재계산
6. 자연스러운 학습 구간 종료에 변경 요약 제공. 사용자 사후 수정·되돌리기 지원

확정한 동일성·이력·교재 원칙:

- 이름 유사도만으로 병합하지 않음. 같은 의미·조건의 표현은 기존 ID에 표현·출처 추가
- 같은 지식의 설명을 교정할 때는 변경 전후·이유와 새 버전 보존. 적용 조건·범위가 다른 주장은 별도 ID로 유지하고, 판단이 모호하면 별도 후보로 남김
- 근거가 부족하면 미확정 상태로 저장. 사용자 승인을 매번 요구하지 않되 확정 교재·정답 기준으로 사용하지 않음
- 병합 전 ID·출처·당시 지식 버전·수행 근거 연결을 추적 가능하게 유지. 잘못된 병합을 풀어도 무관한 기록·진도는 보존
- 과거 답안은 당시 버전에 보존. 중앙 내용 수정 때문에 기존 응답을 소급 변경하지 않음
- 교재는 설명 흐름·예시·프로젝트 맥락을 묶어 구성. 명제마다 파일·카드 하나를 강제하지 않음
- 문법·참조 구조는 코드로 검증하고 의미 동일성은 에이전트가 판단. 자동화가 모든 의미 오판을 막는다고 주장하지 않음

구체적 구현·복구 제안:

- 버전 이력은 자동 커밋 여부와 독립적으로 보존. Git HEAD만으로 저장 전 설명을 복구한다고 가정하지 않음
- 교재 관리 영역에 지식 ID·버전·직전 생성 내용의 식별값 보존. 직접 수정이 탐지되면 보존·비교 후 반영, 자동 덮어쓰기 금지
- 교재 갱신은 의미 단위의 자동 관리 영역에 한정. 개인 메모·프로젝트 예시·실습·답안은 제외
- 공통 설명의 변경으로 예시가 부정확해질 수 있으면 재검토 상태 표시. 이전 버전 교재를 최신으로 표시하지 않음
- 다중 파일 갱신 중단에 대비해 변경 단위를 식별하고 재시도 가능하게 설계. 단순 파일 rename 하나로 전체 원자성을 보장한다고 가정하지 않음
- 변경 요약은 새 필수 승인 단계가 아님. 사용자가 요청하면 언제든 상세 이력 확인

## 설계 4 — 지식별 통합 복습

**상태: 명제별 통합 일정·묶음 질문·실제 확인 범위별 근거 연결, 마지막 간격 뒤 종료·오답 시 짧은 간격부터 재시작·최초 기준일은 챕터 완료일·기존 복습의 통합 이전 방향은 확정. 하루 복습 양은 고정 제한 없음, 간격 +1/+3/+7/+14일, 힌트 후 정답은 처음 간격부터, 마친 redis 스터디의 복습 자동 시작 없음으로 확정. 시간대·날짜 계산·이전 세부는 [추천안](storage-recovery-migration.md) 검토 중.**

확정한 복습 경험과 근거 원칙:

- 명제 ID마다 기본 복습 일정 하나. 챕터·프로젝트별로 같은 일정 복제 금지
- 프로젝트·챕터는 복습 범위 필터. 같은 명제라도 적용 맥락과 독립 수행 여부는 분리
- 연관 명제를 한 설명·문제로 함께 확인 가능. 명제마다 질문 하나를 강제하지 않음
- 답변 하나가 여러 명제를 다뤄도 실제 확인한 범위에만 수행 근거 연결. 주제 전체를 일괄 이해 완료로 처리하지 않음
- 전체 추론은 사슬/복합 과제 수행으로 별도 확인. 전제를 각각 외운 것과 논증을 독립 수행한 것은 다름
- 새로운 프로젝트에서 같은 지식을 만났다는 사실만으로 다음 회상 시점을 미루거나 완료하지 않음

기록·완료·레거시 연결의 세부 제안:

- 독립 응답 → 판정 → 필요한 보충 → 교정 확인 순서 유지. 최초 응답과 교정 직후 응답을 별도 보존
- 회상 성공과 지식 수정의 검토 상태 구분. 내용이 실질적으로 바뀌었다면 변경 부분의 확인 필요성을 기록
- 과거 학습 근거를 통합 일정 충족에 사용할지는 해당 시간·범위·도움 조건에 대한 규칙으로 판단. 정책 없이 날짜만 맞춰 완료 처리 금지
- STRONG 등 정확성 표지는 해당 응답의 평가이며 장기 기억 정착 인증이 아님. 정한 마지막 회차를 실제로 마치면 주기 종료, 이후 회차 자동 추가 없음
- 본 학습에서 다루지 않은 내용은 새 학습 필요로 분류. 복습 오답으로 위장 금지
- 원 응답은 프로젝트의 진단/실습/시험 또는 루트의 통합 복습 기록 중 발생 위치에서 보존. 중앙 조회를 위해 두 번째 편집 가능한 응답 정본을 만들지 않음
- 기존 챕터 회차의 completed는 과거 주기 완료로 보존. 검증 없이 새 지식별 주기의 완료로 복제하지 않음. 새 통합 복습도 정한 마지막 회차 뒤에는 종료하는 유한 주기

확정한 운영 방향:

- 마지막 간격 뒤 자동 연장 없이 종료. 오답이면 짧은 간격부터 다시 시작
- 하루 복습 양은 고정 제한 없음. 시간·질문 수·내용 수로 자동 종료하지 않으며 사용자가 원할 때 중단·재개. 남은 복습은 미완료로 보존하고 예정일을 자동 변경하지 않음. 미래 회상 당기기나 같은 내용의 여러 회차를 하루에 완료하는 것은 별개이며 기본 금지 유지
- 최초 기준일은 챕터 완료일. 기존 일정이 있는 같은 내용은 다른 챕터에서 만났다는 이유만으로 초기화하지 않음
- 기존 챕터별 복습은 새 통합 복습으로 이전. 과거 원 응답·이력 보존, 하지 않은 복습의 성공 기록 생성 금지. 실제 이전은 상세 계약과 dry-run 이후의 별도 단계

남은 세부 제안과 미결:

- 확정: 간격 +1/+3/+7/+14일. 힌트를 받고 맞히면 오답과 같이 처음 간격부터 재시작
- 확정: redis ch-03·ch-04는 건너뛴 선택 유지, ch-01·ch-02는 원할 때만 시작. 이전 과정의 자동 일정 생성 금지
- 추천: 시간대 기본값 `Asia/Seoul`, 늦게 복습하면 실제 복습일부터 다음 날짜 계산, 오답 재시작 기준일은 틀린 날
- 오답을 낸 내용만 재시작하고 함께 물은 다른 내용의 일정은 보존하는 방식 제안. 도움받은 답·부분 정답의 처리도 별도 정의
- 초기 버전에 별도 기억 확률 모델·자동 간격 최적화 알고리즘을 필수로 추가하지 않음
- 기존 약속된 날짜를 자동으로 재배정하지 않음. 통합 시 충돌·중복 일정을 보여주고 이전 정책으로 처리
- 미래 회상 당기기, 밀린 여러 회차를 같은 날 처리하기, 학습자 동의 없는 일정 이동을 기본 동작으로 두지 않음

## 설계 5 — 저장소와 구성 요소

**상태: 루트와 기존 프로젝트 배치는 확정. 저장 형식·모듈 계약은 제안.**

```text
study/
├── .study/          # workspace 등록·설정, 로컬 상태는 분리
├── knowledge/       # 공통 지식·관계·출처·변경 이력
├── review/          # 지식별 통합 일정과 새 회상 기록
├── backlog/
└── study-*/         # 기존 위치 유지: 교재·실습·평가·진행
```

### 저장과 이식성

- 초기 저장은 Markdown + 검증 가능한 구조화 메타데이터 제안. 외부 그래프 DB나 별도 서버 설치는 기본 요구에서 제외
- 설명은 사람이 읽고 수정할 수 있는 Markdown, 관계·식별자·버전·일정은 명시적 구조로 관리
- 같은 내용을 Markdown과 DB에 동시에 원본으로 두지 않음. 검색·그래프 색인은 재생성 가능
- 루트 manifest로 학습 저장소 식별, 프로젝트는 안정 ID와 루트 상대 경로로 등록
- 실행에 필요한 절대 경로는 현재 루트에서 계산. PC별 외부 파일 매핑·서버 포트·캐시는 추적 대상 학습 자료와 분리
- 현재 `/Users/jimmylee/IdeaProjects/study`를 하드코딩하지 않음. 상세는 [저장소 구조 초안](workspace-design.md) 참고

### 책임 경계

| 구성 요소 | 책임 | 기존 코드와의 접점 |
|---|---|---|
| 저장소·프로젝트 탐색 | 루트 등록, 대상 선택, 상대 경로·쓰기 범위 검증 | `src/project/` |
| 대화형 진단·수업 진행 | 질문 준비, 응답 연결, 경로 선택, 종료·재개 | `src/session/`, phase 지침 |
| 지식 관리 | ID, 내용·조건·관계·출처, 버전, 변경·병합 | 새 기능 모듈 후보 |
| 학습 근거 연결 | 원 응답·판정·도움·실행과 당시 지식 버전 연결 | assessment/lab/session 기록 계약 |
| 교재 갱신 | 공통 관리 영역 렌더, 충돌 감지, 최신화 상태 | 현재 concept/README 지침 |
| 통합 복습 | 지식별 일정, 대상 조회, 회상 기록, 레거시 연결 | `src/review/` |
| 화면 | 작은 위젯, 필요할 때 지도·표·상세 보기 | Pi widget, 기존 browser bridge |

- `index.ts`는 등록과 의존성 조립만 유지. 새 업무 로직 집중 금지
- 순수 도메인 로직과 Pi/파일/브라우저 adapter 분리. 테스트 때문에 실제 학습 자료나 브라우저를 요구하지 않음
- 공통화는 실제 중복만 대상. 대화형 진단과 HTML 시험의 다른 종료·제출 계약을 억지로 같게 만들지 않음
- 정확한 새 명령·도구 이름, 파일 스키마, 라이브러리는 구현 계획 전 검토 대상

### 화면과 학습 위치

- 위젯: 현재 프로젝트·챕터·단계·지식·다음 행동을 짧게 표시
- 지도: 요청 시 현재 목표 주변부터 열고 전체 지식·관계 유형·상세·표로 탐색
- 탐색 중 선택한 노드와 실제 학습 위치는 다른 상태. 보기 선택만으로 phase·학습 경로 변경 금지
- 학습 경로 변경 시 이유 기록. 화면 표시는 경로와 근거의 뷰이며 상태의 원본이 아님
- 최초 지도는 읽기 중심 제안. 수정 요청은 Pi로 전달하며 시각적 그래프 편집기까지 필수로 만들지 않음
- 연결선과 노드 색상은 선택/관계 의미를 우선 표시. 근거 없는 숙련도 색상·백분율 사용 금지

## 실패 처리와 안전 경계

| 상황 | 처리 제안 |
|---|---|
| 자료 접근 실패·출처 상충 | 접근/검증 범위 표시, 필요한 입력 요청. 읽지 않은 자료의 요약이나 확정 주장 생성 금지 |
| 루트 불명·여러 프로젝트 | 명시 선택 또는 복구 안내. 새 저장소·첫 프로젝트 임의 선택 금지 |
| 진단 중단·세션 재개 | 질문 ID·원 응답·평가 단계·미확인 범위로 재개. 동일 제출 중복 평가 방지 |
| 정답 기준 오류 | 최초 기준 보존, 문항 무효/정정 사유 표시. 조용한 사후 기준 변경 금지 |
| 지식 동시 수정 | 예상 버전 불일치 탐지, 다른 변경 덮어쓰기 금지. 재검토·재적용 |
| 중앙 반영 일부 실패 | 변경 단위와 미완료 연결 보존, 재시도. 완료되지 않은 반영을 성공으로 표시하지 않음 |
| 교재 자동 영역 직접 편집 | 사용자 내용 보존, diff·충돌 안내. 해결 전 이전 버전 표시 |
| 관계·병합 오류 | 관련 변경만 되돌리기. 이력과 무관한 학습 응답·진도는 보존 |
| 실행 검증 실패 | 실습 완료·독립 수행으로 승격 금지. 원인과 실제 결과만 기록 |
| 위젯·지도·복습 안내 페이지 실패 | 표시 실패 경고. 이미 저장한 학습 근거·통과한 시험을 무효화하지 않음 |
| 학습 근거 또는 phase 저장 실패 | 저장 여부를 명확히 구분, 성공처럼 보고하지 않음. 재개/복구 가능 상태 보존 |

보안·실행 경계:

- 로컬 브라우저는 기존 loopback·세션 식별·제출 유효성 검증 계약 유지/점검
- 자료 문서·HTML·학습자의 응답은 데이터. 지침으로 실행하거나 경로·도구 권한을 자동 확장하지 않음
- 루트 공통 영역과 프로젝트 내부의 쓰기 권한을 분리. 기존 projectPath 범위 검사를 해제하는 방식 금지
- 파일 경로 탈출·심링크·기존 내용 덮어쓰기 검증. 외부 폴더를 자동 대량 수집하지 않음
- 답안은 제출 전 공개 payload에서 제외하고, 렌더링 시 자료·응답의 HTML/스크립트 삽입 방지
- 자동 지식 반영은 무제한 Git publish 권한이 아님. 기존 checkpoint의 승인된 파일만 커밋·푸시하는 계약 유지
- 음성 입력은 사용자 수단을 통해 제공된 텍스트로 취급. 측정하지 않은 음성 특성·시간·유창성 추정 금지

## 검증 전략

### 자동화 검증

1. **학습 단계**
   - 대화형 진단에서 최소 10문항/HTML reopen 강제 제거가 새 진단에만 적용되는지 확인
   - 상한·설명 요청·중단·재개, 미확인 보존, 질문/제출 ID의 멱등성 확인
   - 개념 후 실습 순서와 기존 HTML 시험 제출·결과 확인·필수 근거 검증 유지
2. **평가와 근거**
   - 출제 전 기준 저장, 제출 전 답안 비노출, 문항 정정의 원본 보존
   - 설명 제공·자기보고·힌트 후·독립 응답·실행 성공을 구분
   - learner observation/takeaway 없는 lab 완료, checkpoint만으로 phase 완료, 날짜만으로 복습 완료 거부
3. **지식과 교재**
   - 조건이 다른 동명 지식의 오병합 방지, 전제 묶음 보존, 과거 ID/버전 조회
   - 변경 후 교재 관리 영역만 갱신, 개인 메모·답안 불변, 충돌 시 보존
   - 변경 단위 재시도·되돌리기·동시 수정·중간 실패에서 유실/중복 없음
4. **루트와 복습**
   - 다른 절대 경로로 옮긴 fixture에서 같은 지식·프로젝트·기록 연결
   - 동일 지식의 여러 프로젝트 연결에도 기본 일정 중복 없음, 맥락별 근거 유지
   - legacy manifest/일정/상태 보존, 기존 completed 소급 재해석 금지
   - 루트 밖·심링크 경유 쓰기 차단
5. **기존 기능 회귀**
   - curriculum 승인, HTML 시험 attempt·ack, preflight/lab, checkpoint Git 안전장치, browser lifecycle, extension 등록 경계
   - 기본 테스트는 실제 사용자 study 저장소 대신 임시 fixture 사용

### 실제 사용 파일럿

- 선택한 한 챕터로 대화형 진단 → 개념 → 기존 실습 → HTML 시험 → 통합 복습 연결 검증
- 별도 프로젝트에서 같은 지식을 다시 만나는 재사용 사례 확인
- 진단 질문 수·반복 질문·불필요한 중단, 힌트 수준, 독립 설명·새 맥락 적용, 실제 지연 회상 근거 관찰
- 만족도나 시험 정답률만으로 장기 기억 향상을 단정하지 않음
- 현재 단계에서는 위 테스트를 실행한 것이 아니라 검증 계획을 작성한 상태

## 이전과 도입 순서

1. **루트·기록 계약:** 기존 폴더 이동 없이 등록·상대 참조·원본 보존 지원
2. **대화형 진단·개념:** 기존 test와 분리된 새 진단 경로, 질문/답변 근거 계약
3. **중앙 지식·교재:** 선택 프로젝트에 지식 연결·버전·관리 영역·자동 최신화 적용
4. **통합 복습:** 이전 일정·회차와 충돌을 확인한 뒤 지식별 일정 연결
5. **화면·전체 회귀:** 작은 위젯·읽기 중심 지도, 재개·이동성·실패 복구 파일럿

- 위는 의존성을 설명하는 설계 순서이며 파일별 구현 체크리스트가 아님
- 기존 학습 자료 전량 자동 재생성·자동 파괴적 이전 금지. dry-run, 대상 범위, 백업·되돌리기 확인 후 실제 전환
- 구형 HTML 진단과 챕터 회차 기록은 과거 근거로 보존. 새 대화형 진단·통합 복습으로 거짓 소급 변환 금지
- `study-init.md` 등 현재 지침의 구형 진단/복습 설명과 최신 phase 지침 간 불일치도 수정 대상에 포함. 새 설계와 낡은 생성 문구의 동시 배포 방지
- 최종 설계 승인 후 격리된 구현 브랜치/작업 공간과 구현 계획을 별도로 준비
