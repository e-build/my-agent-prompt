STUDY / KNOWLEDGE DESIGN / DISCUSSION DRAFT

같은 지식을, 어디에 둘까?

세 안 모두 그래프로 그릴 수 있습니다. 차이는 그림이 아니라 무엇을 하나의 지식으로 저장하는지, 그리고 내용을 어디서 고치는지입니다.

검토 결과: ② 공통 지식 저장소 방향 선택. 지식은 하나로 관리하고, 학습 프로젝트는 필요한 맥락에서 참조합니다. 선택한 방향의 실제 지식 그래프 예시 보기 →

세 그림에서 공통으로 사용할 가상의 예시 각 연산이 원자적이어도, 연산을 여러 개 묶은 전체 동작까지 원자적인 것은 아니다.

추가 동기화가 없는 상황을 가정합니다. 캐싱 교재에서는 GET → 계산 → SET으로, 동시성 교재에서는 공유 값의 읽기 → 계산 → 쓰기로 설명합니다. 두 문서는 예시가 다르지만 같은 원칙을 다룹니다.

① 교재 + 의미 인덱스 ② 공통 지식 + 프로젝트별 활용 ③ 교재끼리 링크 한눈에 비교
01
초기 추천안 · 비교용으로 보존

교재는 그대로 두고, 같은 의미를 하나의 지도 항목으로 묶기

본문의 원본은 각 프로젝트 README입니다. 별도 인덱스는 두 문서가 같은 원칙을 다룬다는 사실을 구조화합니다. 교재 문장을 하나로 합치거나 다른 교재에 덮어쓰지 않습니다.

“설명을 고치고 싶다”면?

캐싱 설명이 잘못됐다면 캐싱 README를 수정합니다. 지도는 해당 출처와의 일치 여부를 다시 확인합니다. 동시성 README까지 자동으로 고치지는 않습니다.

두 교재가 실제로 다른 조건을 말하고 있었다면 K17을 나누거나 연결을 해제합니다. 본문 수정과 ‘같은 지식인가’의 판단은 다른 작업입니다.

얻는 것 / 감수하는 것

  • 각 프로젝트를 따로 읽어도 완결된 교재가 됩니다.
  • “이 원칙을 어디에서 배웠지?”를 명제 기준으로 찾을 수 있습니다.
  • 중복 설명은 남습니다. 두 교재의 일관성을 자동 보장하지는 않습니다.
02
사용자가 선택한 방향

공통 원칙을 한곳에서 관리하고, 프로젝트는 가져다 쓰기

공통 설명의 원본은 중앙 지식 저장소입니다. 프로젝트 교재에는 그 지식의 참조와 프로젝트 고유 예시를 둡니다. 중앙 저장소는 Markdown으로도 만들 수 있으며, 특정 DB를 뜻하지 않습니다.

“설명을 고치고 싶다”면?

공통 원칙이 잘못됐다면 중앙 K17을 수정합니다. 두 프로젝트는 수정된 버전을 언제 반영할지 결정합니다. 예시 자체의 오류는 해당 프로젝트에서 고칩니다.

단권화도 가능합니다. 공통 설명을 포함해 교재를 생성하면 됩니다. 다만 생성본을 직접 수정하지 않고 원본에서 고치며, 갱신 규칙을 마련해야 합니다.

얻는 것 / 감수하는 것

  • 공통 설명을 한곳에서 개선할 수 있습니다.
  • 지식 중복을 본문 수준에서 줄일 수 있습니다.
  • 공통 설명의 수정이 여러 프로젝트에 미치는 영향과 버전을 관리해야 합니다.
03

교재끼리 “관련 내용은 여기” 링크만 달기

본문은 각 README에 있고, 별도 K17 같은 지식 항목은 없습니다. 문서의 절과 절을 연결합니다. 사람이나 에이전트가 두 본문을 읽어야 같은 원칙인지, 비슷한 다른 원칙인지 판단할 수 있습니다.

“설명을 고치고 싶다”면?

해당 README를 수정하면 됩니다. 문서 이동이나 제목 변경으로 링크가 깨지지 않았는지만 확인합니다.

다른 교재에도 같은 오류가 있는지 확인하려면 본문을 찾아 읽어야 합니다. 링크가 있다는 것만으로 동일한 명제를 다룬다고 확정할 수는 없습니다.

얻는 것 / 감수하는 것

  • 가장 단순하며 지금 Markdown 체계에 바로 적용하기 쉽습니다.
  • 관련 문서를 찾아가는 탐색에는 충분합니다.
  • 지식의 중복 통합과 전제 묶음 → 결론 조회에는 구조가 부족합니다.

THE ACTUAL DECISION

①과 ③은 ‘저장 단위’, ①과 ②는 ‘수정할 원본’이 다릅니다.

구분① 교재 + 의미 인덱스② 공통 지식 + 활용③ 문서 링크
본문을 고치는 곳각 프로젝트 README공통 설명은 중앙 지식
고유 예시는 각 프로젝트		각 프로젝트 README
별도 저장하는 것명제·조건·추론 관계·원문 출처공통 설명·명제·관계·버전·근거문서/절 사이의 링크
같은 원칙을 두 번 배움지식 하나에 출처 두 개지식 하나를 두 프로젝트가 참조본문 두 개가 링크로 연결됨
단권화 교재현재의 독립 교재 유지참조 또는 공통 내용 포함 생성현재의 독립 교재 유지
운영 부담추출·중복 판단·출처 변경 감지공통 내용 편집·버전·영향 관리링크 정리·깨진 링크 확인

선택은 ②입니다. 사용자의 이해와 기억을 위한 지식은 공통 저장소에서 하나로 관리하고, 프로젝트는 필요한 지식을 각자의 맥락에서 참조합니다. 프로젝트별 단권화는 공통 설명과 고유 예시를 묶어 읽는 형태로 설계합니다. 참조 버전·갱신·편집 규칙은 후속 결정 대상입니다.

범위: 지식 내용의 관리 구조만 비교했습니다. 학습자의 실제 응답·힌트·실행 증거·숙련도와 현재 수업 경로는 별도 기록이며 이 그림에서 생략했습니다. 그림의 K17, 파일 경로, 버전은 설명용 예시입니다. 최종 스키마나 구현 계획은 아닙니다.
