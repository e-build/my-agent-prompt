## 사용자가 선택한 방향

| 결정 | 대화 근거 | 반영 범위 |
|---|---|---|
| 개념 학습 후 프로젝트 실습 | 학습 흐름 질문에 `개념 후 실습 유지` 선택 | 개념과 실습을 작은 단위로 상시 왕복시키는 방식은 기본값에서 제외 |

| 공통 지식을 중앙에서 관리 | `knowledge-options.html`의 ②에 “이게 정확할것 같아” 및 필요한 곳에서 맥락에 맞게 참조한다는 설명 | 공통 내용의 정본은 중앙 지식 저장소. 프로젝트는 공통 지식 참조와 고유 맥락·예시를 보유 |
| 그래프의 개략 방향 확인 | 지식 관계도·추론 상세도 설명 후 “확인” | 공통 지식을 점으로, 의미가 다른 관계를 구분해 표현. 지식 내용과 학습 근거를 연결하되 구분하고, 같은 지식을 여러 맥락에서 활용하는 방향. 세부 스키마·화면·운영 정책까지 확정한 것은 아님 |

| 단권화는 본문 포함·자동 최신화 | 단권화 갱신 질문에서 `본문 포함·자동 최신화` 선택 | 중앙 지식의 공통 설명을 프로젝트 README에 포함하고 관리 영역만 자동 갱신. 프로젝트 고유 내용·개인 메모·과거 기록은 보존. 기존 교재의 즉시 변환 승인은 아님 |
| 작은 상태 위젯 + 필요할 때 지도 열기 | 지도 표시 질문에서 `작은 상태 위젯 + 지도 열기` 선택 | Pi에는 현재 위치·다음 단계만 상시 표시하고 그래프는 별도로 열기. 우측 고정 도킹·좌우 분할·별도 지도 창의 상시 배치는 요구에서 제외 |
| 완료 테스트는 기존 HTML 유지 | 완료 테스트 질문에서 `기존 HTML 시험 유지` 선택 | 진단·개념·실습은 Pi 중심, 챕터 완료 시험은 기존 브라우저 assessment 흐름 유지. Pi 대화형 시험으로 대체하거나 두 시험 UI를 새로 지원하지 않음 |
| 지식별 통합 복습 | 복습 단위 질문에서 `1` 선택 | 공통 지식별 복습 일정과 이력 관리. 프로젝트·챕터는 범위 필터이며, 적용 맥락·독립 수행·도움 여부는 구분. 기존 챕터 회차의 즉시 변환 승인은 아님 |
| 하나의 study 루트에서 전체 학습 관리 | “현재 복습만이 아니라 파일구조…PC 마다 프로젝트의 경로는 달라질수 있지만 핵심은 하나의 study 프로젝트안에서 관리” | 공통 지식·복습·주제별 프로젝트·백로그를 같은 학습 저장소에 보관. 현재 PC의 위치는 `/Users/jimmylee/IdeaProjects/study`이며 고정 경로 계약이 아님. 기존 폴더 재배치·데이터 변환은 별도 단계 |
| 기존 프로젝트 위치 유지 | 루트 내부 구조 질문에서 `현재 위치 유지` 선택 | 루트 바로 아래의 기존 `study-*` 폴더를 이동하지 않고 `.study/`·`knowledge/`·`review/` 공통 계층 추가. `projects/` 재배치는 이번 범위에서 제외. 실제 파일 생성·이전은 아직 미승인 |
| 학습 루프와 진단 종료 기준 | 학습 흐름 검토에서 `이 흐름으로 확정` 선택 | 경로를 결정하면 진단 종료, 기본 상한 8문항과 미확인 보존. 유연한 설명·예측·확인 후 프로젝트 실습, 과제별 도움 수준 선택, HTML 시험 유지. 진단/수업은 책임과 전달 정보를 분리하며 별도 프로세스까지 필수로 요구하지 않음 |
| 다이어그램 기본 밝은 스타일 | 스타일 질문에서 기본 밝은 스타일 선택 | 이번 설계 설명용 HTML에 적용. 전역 스킬 설정이나 프로젝트 마커 변경 없음 |
| 지식의 기본 단위는 명제 | 지식 기본 단위 질문에서 `명제 중심으로 확정 (Recommended)` 선택 | 구체적인 주장·조건·범위를 저장·재사용의 기준으로 사용. 큰 개념은 우선 이름·태그·목록으로 탐색하고 별도 Concept 원본 계층은 도입하지 않음. 설명·예시를 문장마다 노드로 나누지 않음. 세부 분해·관계·수정·복습 정책까지 일괄 승인한 것은 아님 |
| 명제의 분해 수준은 그림 2의 예시 수준 | 명제 분해 수준 질문에서 `예시 수준 채택 (Recommended)` 선택 | 독립적으로 참조·검증·질문·수정할 주장은 분리. 논증 연결이 없어도 재사용할 정의·규칙·판단 기준은 보존. 풀이·비유·일회성 실행 결과는 관련 설명이나 프로젝트 기록에 유지. 관계·수집 검증·수정·복습 정책의 일괄 승인은 아님 |
| 추론·선수 학습·적용 맥락 구분 | 관계의 의미 질문에서 `이 구분으로 확정 (Recommended)` 선택 | 공동 전제 묶음과 같은 결론의 독립 논증을 보존. 목표별 학습 순서와 프로젝트 적용은 추론과 다른 의미로 관리하며 지도에서는 함께 탐색 가능. 관계의 저장 형식·화면 개수·수집 검증·수정·복습 정책 승인과는 별개 |
| 지식 후보의 근거와 사용 가능성 구분 | 수집·사용 기준 질문에 `1 - 나머지 5,6도 너가 권장한대로 진행` 응답 | 자료·교재·교사 설명에서 후보 수집, 출처·조건·불확실성 확인. 미확정도 보존하되 확정 교재·정답 기준으로 사용 보류. 학습자 답변은 수행 근거로 별도 보존. 자동 반영 후 사후 검토 유지 |
| 보수적 동일성 판단과 교정 이력 보존 | 위 응답에서 검토 5의 추천안 채택 | 같은 의미의 표현은 기존 ID에 연결, 같은 지식의 교정은 변경 전후·이유와 새 버전 보존, 범위가 다르거나 모호하면 별도 ID/후보 유지. 과거 답안은 당시 버전에 연결, 병합 해제 시 출처·이전 ID·근거 연결 복구 |
| 세밀한 기록과 묶음 학습 경험 | 위 응답에서 검토 6의 추천안 채택 | 교재·질문은 연관 명제와 맥락을 묶어 구성. 명제별 통합 일정, 실제 확인한 명제에만 수행 근거 연결. 전체 추론 수행은 전제 암기와 별도 확인. 새 맥락에서 봤다는 사실만으로 복습 날짜 이동 금지. 간격·기존 회차 이전의 후속 결정은 아래 행 참고 |
| 정한 마지막 복습 간격 뒤 종료 | “마지막 간격 다음 - 그대로 끝” | 마지막 회차를 실제로 마치면 해당 복습 주기 종료. 이후 간격을 자동 추가하지 않음. 장기 기억 보증과는 별개이며, 이전의 무기한 반복 가능 제안보다 이 선택 우선 |
| 오답이면 짧은 간격부터 재시작 | “틀렸을때 - 짧은 간격부터 다시 시작” | 오답을 낸 내용의 복습 주기를 가장 짧은 간격부터 다시 시작하는 방향. 다른 내용까지 일괄 초기화하지 않는 세부안은 후속 설계. 교정 직후 정답을 지연 회상 성공으로 바꾸지 않음 |
| 최초 복습 기준일은 챕터 완료일 | “시작하는 날 - 챕터를 끝낸 날” | 처음 등록하는 내용의 복습 기준일은 해당 챕터를 끝낸 날. 다른 챕터에서 같은 내용을 다시 만났다고 기존 일정을 자동 초기화하지 않음. 오답 재시작 기준일·완료일 미확인 기록 처리는 후속 설계 |
| 기존 복습은 새 통합 복습으로 이전 | “새 통합 복습으로 마이그레이션” | 기존 챕터별 일정을 새 통합 복습에 연결하는 방향 확정. 원본 답안·이력 보존, 하지 않은 복습의 완료 처리 금지. 날짜·중복 처리·dry-run·복구 계약을 마련한 후 실제 이전은 별도 실행 단계 |

| 하루 복습 양은 고정 제한 없음 | “고정 제한 없음” | 시간·질문 수·내용 수에 따른 자동 종료 상한 없음. 사용자가 원할 때 중단하고 다음에 이어가기. 남은 항목은 미완료로 보존하며 예정일 자동 변경 없음. 미래 회상까지 당겨 수행하거나 같은 내용의 여러 회차를 하루에 몰아 완료하는 허용은 아님 |
| 복습 간격은 +1/+3/+7/+14일 | 저장·복구·이전 추천안의 세 질문에 “추천대로 진행” | 챕터 완료일 기준 네 회차, 마지막 회차 후 종료. 늦게 복습하면 다음 날짜는 실제 복습일부터 계산하는 방식은 추천안 |
| 힌트를 받고 맞히면 처음 간격부터 | 위 응답 | 독립 회상이 아니므로 오답과 같이 짧은 간격부터 재시작. 원 응답에는 “힌트 후 정답”으로 보존 |
| 마친 redis 스터디의 복습은 자동 시작하지 않음 | 위 응답 | ch-03·ch-04는 건너뛴 선택 유지. ch-01·ch-02는 사용자가 원할 때만 시작. 이전 과정에서 일정 자동 생성 금지 |
| 저장·복구·이전 추천안 승인 | 추천안 확인 질문에 “진행해” | 명제별 파일, 버전·병합 표시, 변경 계획 기반 복구, 교재 직접 수정 보류, 루트 표시 파일·상대 경로, 시간대 Asia/Seoul, 늦은 복습은 실제 복습일 기준, 미리 보기 후 이전 |

중앙 지식 선택의 이유: 이해와 기억을 위한 개인 지식을 프로젝트마다 분절하기보다 하나의 저장소로 보고, 필요한 맥락에서 참조하려는 목적.

## 명시된 요구

- 입력은 주제 문자열뿐 아니라 사용자 지정 파일·디렉터리·URL 등의 참조 자료 포함
- 고정 HTML 문항 세트보다 Pi 세션에서 이해를 확인하며 목적·난이도를 조절하는 진단·수업 지향
- 진단 담당과 수업 담당의 역할 구분
- 선수 지식 지도, 수정 가능한 학습 경로, 예측 질문과 확인 질문 구분
- 객관식·자유 서술형 회상, 출제 전 정답 확정, 비채점 질문, 확신도·사고 과정 수집
- 최초 우측 상시 패널 희망은 후속 선택으로 대체: Pi의 작은 상태 위젯 + 필요할 때 지도 열기
- 프로젝트 기반 실습 유지. 실습 내부 방식은 전면 개선 가능
- 완료 테스트는 기존 HTML 시험 유지. 통과·결과 확인·미달 범위 재학습 흐름 보존
- 중앙 지식에 전제 묶음 → 결론, 중복 지식 통합, 그래프·표 탐색, 후속 학습 활용 반영
- 지식별 통합 복습. 동일 지식의 여러 프로젝트 활용은 연결하되 맥락별 수행 근거 구분
- 하나의 study 루트에 전체 학습 자원 보관. PC별 절대 경로가 달라도 지식·프로젝트·기록 연결 유지
- 단권화 README에 공통 설명 본문을 포함하고 자동 최신화. 공통 관리 영역과 프로젝트 고유 내용·개인 메모·과거 기록 구분
- 음성 인식은 사용자가 마련한 입력 수단 사용. 새 음성 서비스 통합 불필요
- 모델·비용·계정 등 Pi가 담당하는 영역은 이번 설계 범위에서 제외
- Markdown 문서와 함께 설명 내용에 맞는 설계 다이어그램 사용. 구조·관계·분기·자료 흐름을 각각 적합한 그림으로 표현
- 설명은 12세도 이해할 수 있는 쉬운 말과 구체적인 예시로 작성. 중간 단계를 생략하지 않고, 어려운 용어는 먼저 풀어 설명. 그림에 내용을 몰아넣지 않으며 표·번호 목록·Mermaid는 이해에 도움이 될 때 사용

## 현재 제안과 미결 사항

**아래는 확정한 원칙과 추가 제안·미결 세부를 구분한 목록. 도입 원칙의 합의를 전체 설계·구현·실제 데이터 변경 승인으로 간주하지 않음.**

1. **그래프의 기본 단위**
   - 결정: 명제를 저장·재사용의 기본 단위로 사용. 이름은 표시용이며 주장·조건·범위로 동일성 판단
   - 결정: 큰 개념은 우선 이름·태그·목록으로 탐색. 별도 Concept 원본 계층 없이, 설명·예시를 문장마다 노드로 나누지 않음
   - 경위: [원본 조사](learnharness-knowledge-model.md)와 [도입 다이어그램](learnharness-adoption-diagrams.html) 검토 후 명시적 선택. 이전 개념/원칙 기본 노드 제안은 저장 단위 기준으로 대체됨
   - 결정: 그림 2의 분해 수준 채택. 독립적으로 참조·검증·질문·수정할 주장은 나누고, 재사용할 정의·규칙·판단 기준도 명제로 보존. 풀이·비유·실행 로그는 관련 설명·프로젝트 기록에 유지
   - 미결: 화면의 초기 묶음·펼침 방식, 실제 추출·검증 절차, 세부 스키마·ID 계약. 예시 수준의 선택을 모든 개별 분해 결과의 사전 승인으로 간주하지 않음
2. **관계의 의미**
   - 결정: 명제 간 추론, 목표별 선수 학습, 프로젝트 적용 맥락의 의미를 구분. 지도에서 함께 탐색 가능
   - 결정: 여러 전제가 함께 필요한 추론은 공동 전제 묶음 보존. 같은 결론에 도달하는 독립 논증은 별도 사슬로 유지
   - 결정: 학습 순서는 목표·학습자에 따라 조절 가능하며 논리적 전제와 별개. 학습 지점 하나가 여러 명제를 참조할 수 있음
   - 결정: 적용 연결은 활용 장소이며 이해 완료의 증거가 아님. 수행 근거는 별도 확인
   - 미결: 추론 타당성 검토 절차·관계 변경 이력·추가 관계 종류·저장 형식·화면 세부. 공동 전제의 접점 표현은 그림의 예시이며 특정 렌더러나 엔티티 계약 확정은 아님
3. **지식 내용과 학습 근거**
   - 결정: 공통 지식과 학습자 원 응답·힌트·실행·지연 회상 기록을 구분. 학습자 답변은 공통 지식으로 자동 승격하지 않음
   - 결정: 수행 근거는 실제 확인한 명제와 당시 버전·맥락에만 연결. 전제들을 각각 아는 것과 전체 추론을 독립 수행한 것은 별도 확인
   - 결정: 자료·교재·교사 설명에서 후보 수집. 지정한 개인 노트는 자료 입력으로 수용하고, 출처·조건·미확정 상태 구분
   - 결정: 미확정도 보존하되 확정 교재·정답 기준에는 사용 보류. 출처 위치나 자동 검토 통과를 참의 보증으로 간주하지 않음
   - 그래프 존재만으로 이해·기억 판정 금지. 현재 이해 추정은 실제 근거에서 도출
   - 미결: 근거 상태의 구체적 스키마·전환 절차, 자료 확인 도구, 질문·응답·버전의 저장 계약
4. **화면**
   - 결정: 작은 상태 위젯을 Pi에 상시 표시하고 필요할 때 지도 열기. 우측 고정 패널이나 터미널 좌우 분할은 구현 범위에서 제외
   - 제안: 위젯은 현재 챕터·단계·지식·다음 행동을 짧게 표시. 지도는 현재 목표 주변에서 열고 전체 탐색·선택 지식 상세로 확장
   - 제안: 탐색 중 선택한 지식과 실제 학습 위치를 구분. 지도 표시 실패가 학습 진행·근거 저장을 막지 않게 구성
   - 기술 근거: 현재 설치된 Pi 공개 API의 입력창 주변 setWidget 활용 가능. 미지원 우측 도킹 API 불필요
   - 미결: 위젯의 정확한 표시 항목·지도 진입 명령/단축키·지도 새로고침 방식
5. **중앙 지식의 운영**
   - 결정: 에이전트의 자동 반영 후 사용자 사후 검토. 의미 수정·병합에 사전 승인을 필수로 두지 않음
   - 결정: 동일성은 보수적으로 판단. 같은 의미의 표현은 기존 ID에 표현·출처 추가, 같은 지식의 교정은 변경 전후·이유를 남긴 새 버전으로 보존
   - 결정: 조건·대상·범위가 다른 주장이나 확신이 부족한 후보는 성급히 병합하지 않음. 불확실한 내용은 미확정 표시
   - 결정: 과거 답안은 당시 버전에 유지. 병합 해제 시 이전 ID·출처·학습 근거 연결 복구, 무관한 학습 기록·진도는 보존
   - 제안: 변경 요약의 구간·영향 표시, 변경 단위 트랜잭션·재시도·충돌 복구의 구체적 구현
   - 결정: 중앙 지식의 위치는 하나의 study 루트 내부. 여러 독립 저장소나 사용자 홈의 전역 지식 원본으로 분산하지 않기
   - 결정: 기존 `study-*` 위치 유지, 같은 루트에 공통 영역 추가
   - 미결: 공통 영역의 내부 파일 형식·지식 ID·반영 시점·버전 참조 형식·분리/되돌리기 절차·출처 위치 표현
6. **단권화와 기존 기록**
   - 결정: 공통 설명을 README 본문에 포함하고 중앙 지식 변경 시 공통 관리 영역만 자동 최신화. 프로젝트 고유 내용·개인 메모·과거 기록 보존
   - 제안: 개념 학습 마무리·학습 정리 시점에 갱신을 묶고, 갱신 실패·편집 충돌·고유 예시의 재검토 필요 여부를 표시
   - 미결: 관리 영역의 표시·직접 편집 처리·갱신 시점·충돌 복구·기존 README의 이전 절차

   - 결정: 과거 응답·수행 기록은 당시 지식 버전에 연결하며 중앙 내용 수정으로 소급 변경하지 않음
