## 상태와 범위

- **사용자 결정:** 하나의 study 루트에서 전체 학습 관리, 지식별 통합 복습, 기존 `study-*` 위치 유지 + 루트 공통 영역 추가
- **미확정:** 공통 영역의 내부 파일 스키마, 루트 탐색·등록 계약, 이전 절차
- 현재 PC의 위치: `/Users/jimmylee/IdeaProjects/study`. 하드코딩할 기본값이나 다른 PC에 강제할 경로가 아님
- 이 문서는 `my-agent-prompt/docs/plans/`의 설계 자료. 실제 study 저장소는 읽기 전용으로 확인했으며 파일 생성·이동·변환 없음
- 구현 코드의 정본은 계속 `my-agent-prompt/runtime/pi/extensions/study/`. 학습자의 지식·교재·실습·이력은 study 저장소에 보관
- 최신 사용자 결정은 [decisions.md](decisions.md) 기준

## 확인한 현재 구조

```text
study/                                  # 현재 Git 저장소 하나
├── .git/
├── README.md
├── backlog/
├── study-backend-optimization-practical-case/
├── study-redis-read-through-lifecycle/
└── study-thread-pool-from-scratch/
```

- 조사한 주제별 하위 디렉터리에 별도 `.git` 없음
- 주제별 README·챕터·실습 앱·진행 상태가 이미 같은 Git 저장소에 공존
- `study/README.md`에도 PC 간 Git 동기화와 단일 저장소 운영 원칙 명시
- 루트의 `.study/`, `knowledge/`, `review/`는 현재 없음
- 주제별 `.study/state.json`에는 절대 `projectRoot` 존재. 루트 이동 시 처리해야 할 호환 항목이며, 이 조사로 실제 실패가 재현된 것은 아님
- 일부 레거시 프로젝트에는 `.study/project.json`이 없으므로 새 등록 과정에서 manifest 존재를 일괄 전제할 수 없음

## 루트와 주제별 프로젝트의 구분

| 구분 | 책임 | 예시 |
|---|---|---|
| **학습 저장소 루트** | 공통 지식, 통합 복습, 주제 목록, 백로그 관리 | `study/` |
| **주제별 학습 프로젝트** | 학습 목표·커리큘럼·챕터·실습·현장 맥락 관리 | `study-thread-pool-from-scratch/` |
| **챕터** | 진단 → 개념 → 실습 → HTML 시험의 학습 단위 | `ch-01-concurrency-and-pooling-basics/` |
| **공통 지식** | 주제·챕터와 독립적인 설명·조건·근거·관계 | 경로와 독립적인 지식 ID |

하나의 학습 저장소를 쓰되, 모든 실습을 하나의 빌드나 앱으로 합친다는 의미는 아님. 주제별 Java·Gradle·서비스 환경과 실행 근거는 해당 프로젝트에 유지.

학습 저장소 루트에서 전체 조회·복습·주제 선택을 지원하고, 하위 프로젝트나 챕터에서 실행해도 같은 루트에 연결하는 방향. 여러 주제가 있다고 무작위로 하나를 선택하거나, 주제 변경 때문에 공통 지식을 복제하는 동작 금지.

## 디렉터리 배치 대안

### A. 기존 위치 유지 + 공통 영역 추가 — 사용자 선택

```text
study/
├── .git/                               # 저장소 하나
├── README.md                           # 전체 학습 안내
├── .study/
│   ├── workspace.json                  # 루트 ID·버전·프로젝트 상대 경로 등록안
│   └── local/                          # PC/프로세스별 상태·캐시, Git 제외안
├── knowledge/                          # 공통 지식·관계·출처·수정 이력
├── review/                             # 지식별 일정과 통합 회상 기록
├── backlog/                            # 기존 학습 요구 보존
├── study-backend-optimization-practical-case/
├── study-redis-read-through-lifecycle/
└── study-thread-pool-from-scratch/
    ├── README.md                       # 프로젝트 안내
    ├── .study/                         # 프로젝트 manifest·학습 진행
    ├── app/                            # 기존 실습 코드 유지
    └── ch-01-.../
        ├── README.md                   # 공통 설명 포함 교재 + 고유 맥락
        ├── diagnosis.md                # 진단 근거
        ├── lab/                       # 실행·관찰·학습 근거
        ├── test.md                    # HTML 시험 시도별 기록
        └── review/                    # 기존 기록 보존·통합 복습 연결
```

- 장점: 프로젝트 경로·기존 링크·실습 위치를 이동하지 않고 공통 계층 추가 가능
- 비용: 주제가 많아지면 루트의 디렉터리 수 증가
- 파일명과 내부 구조는 제안. 특히 `knowledge/`의 저장 스키마와 `review/` 일정 형식은 후속 설계 대상

### B. 주제별 프로젝트를 `projects/` 아래로 모으기 — 미채택 비교안

```text
study/
├── .study/
├── knowledge/
├── review/
├── backlog/
└── projects/
    ├── study-backend-optimization-practical-case/
    ├── study-redis-read-through-lifecycle/
    └── study-thread-pool-from-scratch/
```

- 장점: 공통 영역과 주제별 영역의 경계가 파일 탐색기에서도 명확
- 비용: 기존 링크·루트 탐색·저장 경로·외부 도구 설정의 이전 검증 필요
- 두 안 모두 **단일 Git 저장소·공통 지식·통합 복습**이라는 점은 같음. 별도 저장소·서브모듈 도입 아님

## 정보별 원본과 연결

| 정보 | 원본 위치 제안 | 다른 위치에서의 취급 |
|---|---|---|
| 공통 지식 설명·조건·추론·출처 | 루트 `knowledge/` | ID와 버전으로 참조 |
| 단권화의 공통 설명 | 위 공통 지식 | 챕터 README의 관리 영역에 포함, 자동 갱신 |
| 프로젝트 고유 예시·개인 메모 | 해당 프로젝트/챕터 | 자동 생성 교재 갱신으로 덮어쓰지 않음 |
| 진단·실습·시험 근거 | 해당 프로젝트/챕터 | 중앙에서 ID·위치·당시 지식 버전을 참조. 동일 원 응답의 두 정본 생성 금지 |
| 통합 복습 일정·새 회상 기록 | 루트 `review/` | 프로젝트·챕터는 범위 필터와 탐색 링크 |
| 기존 챕터별 복습 기록 | 원 위치 보존 | 중앙 지식과 연결. 신규 수행이나 완료로 소급 계산 금지 |
| 그래프·검색 색인 | 원본에서 재생성 가능한 파생 자료 | 지식의 별도 정본으로 사용하지 않음 |
| 주제별 단계 진행 | 프로젝트 `.study/` | 지식별 복습·현재 화면 위치와 별도 상태 |

루트에서 통합 관리한다는 이유로 모든 파일을 중앙 폴더 하나에 모을 필요는 없음. 내용의 정본은 하나, 조회 범위는 루트 전체라는 원칙.

## PC와 경로가 달라져도 유지할 계약

1. **정체성과 위치 분리**
   - 지식·프로젝트 ID는 경로나 사용자 이름에서 생성하지 않는 방향
   - 프로젝트 위치는 루트 기준 상대 경로로 등록
   - 문서 내부 링크는 상대 링크로 생성. 파일 탐색을 위한 현재 절대 경로는 실행 시 계산
2. **루트의 명시적 식별**
   - 루트 manifest로 식별하며 폴더 이름이 `study`인지, Git 루트인지에만 의존하지 않기
   - 하위 디렉터리에서는 상위의 루트 marker 탐색, 루트 밖에서는 명시적 경로 또는 PC별 등록 사용
   - 후보가 여러 개이거나 marker가 손상되면 선택/복구 안내. 홈 전체 검색이나 새 루트의 무단 생성 금지
3. **공유할 자료와 로컬 상태 분리**
   - 공통 지식·교재·학습 근거·일정은 Git 추적 대상
   - 서버 포트·프로세스 ID·세션 포커스·재생성 캐시·PC별 외부 자료 매핑은 로컬 상태
   - Git 이동성을 설계하되 자동 커밋·푸시·충돌 병합까지 승인된 것으로 간주하지 않기
4. **외부 참조 자료의 한계 명시**
   - 사용자 지정 URL·루트 밖 파일/디렉터리도 입력으로 수용
   - 외부 로컬 경로는 자료 ID와 PC별 매핑으로 취급하는 방향. 다른 PC에서 없는 자료는 누락 표시
   - 자료를 학습 저장소에 보관할지는 민감성·용량·권한·이용 조건을 고려한 별도 정책 필요. 운영 자료·비밀값의 자동 대량 복사 금지
5. **쓰기 경계 유지**
   - 기존 프로젝트 내부 쓰기 검사를 느슨하게 풀어 중앙 지식을 수정하지 않기
   - 루트 공통 영역 쓰기와 주제 내부 쓰기를 분리하고, 상대 경로 탈출·심링크를 통한 범위 이탈 검증
   - 루트가 달라졌다는 이유로 원본 학습 기록의 역사적 경로 문자열까지 일괄 치환하지 않기

## 복습과 기존 프로젝트의 연결

- 일정의 기본 키는 공통 지식 ID. 같은 지식을 새 프로젝트에서 만나도 별도 중복 일정 생성 금지
- 프로젝트·챕터별 학습 맥락과 실제 독립 응답·힌트 여부는 각각 보존
- 과거 맥락의 성공을 다른 맥락의 수행 성공으로 자동 승격하지 않기
- 복습 간격·시간대·실제 일정 산정은 별도 정책. 통합 복습 선택만으로 적응형 간격 알고리즘까지 선택된 것은 아님
- 기존 챕터 회차·완료 상태는 원본 보존. 통합 일정으로 연결할 때 근거 없이 신규 회상 성공·완료 이벤트 생성 금지
- 장기 통합 복습은 계속 이어질 수 있으므로, 기존 챕터의 `review completed`와 전체 지식의 장기 기억 정착을 동일시하지 않기

## 이전과 실패 처리

- **추가 우선:** 루트 등록·공통 영역 도입 → 대상 프로젝트 선택 → 지식/기록 연결 → 검증 → 교재 자동 관리 영역 활성화 순서 제안
- 기존 사용자 변경과 구형 manifest 누락을 먼저 식별. 학습 프로젝트 전체를 일괄 재생성하지 않기
- 지식 수정·병합 이력과 과거 지식 버전을 복구 가능하게 보존. 병합으로 기존 ID를 참조하는 학습 근거가 끊기지 않게 처리
- 교재 갱신 충돌은 이전 버전 표시와 재시도 대상으로 처리. 개인 편집을 버리거나 학습 성과를 취소하지 않기
- 여러 Pi 세션·PC가 같은 지식을 변경하면 버전 충돌을 탐지. 단순 마지막 저장 우선으로 의미 변경을 조용히 덮어쓰지 않기
- 중앙 조회가 실패했을 때 프로젝트 로컬에 별도 공통 지식 원본을 만들어 분기하지 않기. 근거는 원래 기록 위치에 보존하고 중앙 연결의 미완료 상태 표시
- 실제 이전은 구현·검증 이후 별도 승인된 작업. 이번 논의에서 study 루트나 기존 기록 변경 없음

## 검증 기준

- 루트를 다른 임시 절대 경로에 복제해도 지식 ID·교재 링크·통합 복습 연결 유지
- 루트·프로젝트·챕터에서 실행할 때 같은 학습 저장소를 식별하고, 여러 프로젝트를 임의 선택하지 않음
- 동일 지식을 여러 프로젝트에서 연결해도 원본 지식과 기본 복습 일정의 중복 생성 없음
- 같은 지식의 서로 다른 맥락·힌트 여부·당시 버전 근거 유지
- 공통 설명 수정이 교재 관리 영역에만 반영되고 개인 메모·실습·과거 답안은 불변
- marker 없음·구형 manifest·외부 자료 누락·이전 절대 경로 존재 시 명시적인 안내 또는 호환 처리
- 병합·되돌리기·동시 수정·중단 후 재시도에서 관련 없는 지식/기록의 유실 없음
- 루트 밖 쓰기와 심링크 경유 쓰기 차단
- 그래프 캐시 삭제/재생성으로 학습 상태나 지식 원본에 변화 없음

## 후속 설계

1. 배치 결정 완료: A 채택, 기존 프로젝트 폴더 이동 없음
2. 지식·관계·출처·버전·학습 근거의 최소 저장 계약
3. 대화형 진단의 중단 기준과 개념 학습 루프
4. 지식별 통합 복습의 일정 정책과 레거시 회차 연결
5. [전체 설계 초안](design-draft.md)의 단계별 검토 후 최종 설계 문서 작성. 구현 계획·브랜치 전환·실제 이전은 이후 별도 진행
