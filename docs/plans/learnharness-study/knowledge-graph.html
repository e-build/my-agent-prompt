STUDY / CENTRAL KNOWLEDGE / GRAPH PROPOSAL

하나의 지식, 여러 학습 맥락

01 지식 관계도 02 추론 상세도 03 지식과 나의 학습 근거 04 Pi에서 보는 범위 이전 비교안

중앙 저장소를 ‘큰 상자 하나’로 그리는 대신, 저장소 안의 지식 각각을 점으로 펼칩니다. 프로젝트가 달라도 같은 원칙은 같은 점을 참조합니다.

선택된 방향: 공통 지식을 한곳에서 관리하고, 프로젝트는 필요한 맥락에서 활용.

후속 결정: 저장·재사용의 기본 단위는 명제. 큰 개념은 이름·태그·목록으로 탐색. 아래 그림의 축약 라벨은 별도 Concept 원본 계층이 아닙니다.

이 그림의 범위: 초기 개략 관계도이며 명제 분해·관계 스키마를 확정한 도식은 아닙니다. 후속 도입 검토 그림에서 기본 단위의 결정과 남은 제안을 구분합니다. 그래프는 머릿속을 측정한 결과가 아니라 이해와 기억을 돕는 외부 모델입니다.

아래 지식·ID·프로젝트·학습 기록은 모두 설명용 예시입니다. 기존 파일을 읽어 자동 생성한 실제 학습 그래프가 아닙니다. 밝은 스타일·doc-wide·정적 구조도 2장으로 구성하며, 진도와 숙련도는 주 그래프에서 분리했습니다.

01 / SHARED KNOWLEDGE

같은 지식이 두 프로젝트에서 쓰여도, 점은 하나

선택한 지식은 K17 — 개별 연산의 원자성만으로 복합 동작의 원자성은 보장되지 않음입니다. 왼쪽은 이해에 필요한 토대, 오른쪽 위는 이어서 배울 원리, 오른쪽 아래는 그 지식을 사용하는 두 맥락입니다.

  1. 같은 ID는 같은 지식. 캐싱용 K17과 동시성용 K17을 따로 만들지 않음.
  2. 선수 관계와 논리적 함의는 다름. “이것을 먼저 배우면 좋다”가 “이 전제로 결론이 증명된다”는 뜻은 아님.
  3. 노드 이름은 짧게, 내용은 상세에서. 중심 개념의 기준 설명·적용 조건·반례·근거 자료는 노드를 열어 확인.

그림은 일부 지식만 보여주는 예시입니다. 프로젝트 전체와 모든 관련 개념을 숨긴 것뿐이며, 실제 그래프가 이 여섯 항목으로 끝난다는 뜻은 아닙니다. 현재는 개념/원칙 단위를 제안하며 정확한 분해 수준은 미확정입니다.

02 / PREMISES TO CONCLUSION

“왜 그런가?”는 전제를 묶는 추론 노드로

이번에는 K17의 한 반례를 펼칩니다. 같은 카운터를 두 작업이 1씩 증가시키는 모델에서, 두 작업이 같은 이전 값을 읽고 둘 다 그 값에 1을 더해 쓰면 갱신 하나가 유실됩니다.

핵심: 그래프의 모든 선을 ‘관련 있음’으로 만들지 않기. 선수 관계, 전제 → 결론, 적용 사례는 각각 다른 관계로 저장하고 필요한 종류만 표시.

첫 그림의 개념/원칙 지도와 둘째 그림의 조건부 명제/추론은 같은 지식 저장소를 다른 상세 수준으로 보는 제안입니다. 현실의 메모리 모델·서비스 장애·재시도까지 검증한 사례는 아니며, 이 단순 모델의 가정을 벗어나면 결론도 다시 확인해야 합니다.

03 / ONE NODE, TWO KINDS OF RECORD

K17을 선택하면: 지식의 설명과 나의 학습 근거를 함께

개인 지식 저장소는 하나로 두되, 지식 내용과 내가 그 지식을 사용한 기록은 다른 항목으로 연결하는 방식입니다. 기록 하나로 영구적인 이해·기억 상태를 확정하지 않습니다.

CONTENT / K17

이 지식은 무엇인가?

  • 기준 설명: 개별 연산의 원자성만으로 복합 동작의 원자성은 보장되지 않음.
  • 조건: 각 연산의 보장만 주어졌으며 전체 동작을 묶는 추가 보장은 가정하지 않음.
  • 예시·반례: 읽기 → 계산 → 쓰기에서의 갱신 유실.
  • 관계: 선수 지식, 적용 사례, 이를 뒷받침하는 추론.
  • 출처: 실제 학습에 사용한 문서의 위치·URL·버전과 근거를 연결.
  • 변경: 설명 수정 이력 보존. 조건이 다른 지식은 이름이 같아도 무조건 합치지 않음.

LEARNING EVIDENCE / ILLUSTRATIVE ONLY

나는 무엇을 실제로 해봤는가?

다음은 가상 기록입니다. 사용자의 실제 이력이 아닙니다.

  • 캐싱 맥락: 힌트 후 원리를 설명했다는 응답 기록.
  • 동시성 맥락: 새로운 예시에 독립 적용했는지는 미확인.
  • 지연 회상: 시간이 지난 뒤 다시 설명했는지는 미확인.
  • 확인 근거: 원 응답, 과제 조건, 힌트, 실행 결과, 수행 시점, 당시 지식 버전.

표시는 ‘숙련 82%’보다 무엇을 어떤 도움으로 했는지가 우선입니다. 자기보고 확신도도 별도 보존합니다.

중앙 설명이 바뀌어도 과거에 실제로 한 답변이나 실행 결과를 다시 써서는 안 됩니다. 과거 기록은 당시 버전과 연결하고, 바뀐 부분에 대해 필요한 확인만 새로 진행하는 방향입니다.

04 / SAME GRAPH, DIFFERENT VIEWS

Pi에는 작은 상태 위젯, 지도는 필요할 때 열기

화면보이는 것역할
Pi 상태 위젯현재 챕터·단계·지식과 다음 행동의 짧은 요약대화를 가리지 않는 상시 위치 안내. 지도는 필요할 때 열기
전체 지식 지도공통 지식의 묶음, 프로젝트를 넘는 연결전체 구조 탐색, 겹치는 부분과 다음 관심사 찾기
현재 목표 주변 지도현재 노드, 필요한 선수 지식, 다음 후보와 진행 경로필요할 때 여는 지도의 기본 화면으로 제안
선택 지식 상세설명·조건·추론·출처·프로젝트별 적용·학습 근거왜 연결되는지, 무엇이 아직 미확인인지 검토

현재 경로는 변경 가능한 계획입니다. 에이전트가 학습자의 답에 따라 다음 위치를 바꿔도, 지식 자체나 과거 학습 근거를 지우지는 않습니다. 프로젝트를 바꿔도 공통 지식 ID는 유지됩니다.

단권화도 같은 지식의 다른 읽기 방식입니다. 공통 설명을 프로젝트 순서로 배치하고 프로젝트 고유 예시·실습 맥락을 덧붙여 읽습니다. 공통 설명은 README 본문에 포함하고 관리 영역만 자동 최신화하는 것으로 결정했습니다. 프로젝트 고유 내용·개인 메모·과거 기록은 보존하며, 정확한 참조 버전·충돌 처리 규칙은 후속 설계 대상입니다.

현재 제안: 지식 저장소는 하나. 그 위에 전체 탐색, 현재 학습 경로, 단권화 교재라는 서로 다른 보기를 제공.

구현 상태: 이 파일은 논의를 돕는 정적 예시이며, 검색·노드 편집·자동 추출·실시간 패널은 구현하지 않았습니다. 표시 방식은 작은 상태 위젯과 필요할 때 여는 지도로 결정했으며, 우측 고정 도킹 패널은 구현 범위에서 제외했습니다. 그래프 DB·렌더링 라이브러리·파일 배치도 아직 선택하지 않았습니다.
