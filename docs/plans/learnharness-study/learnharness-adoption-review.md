## 검토 목적과 상태

- 요청: LearnHarness의 지식 체계를 우리 study에 적용하는 방법과 사용자 검토 항목 정리
- **검토 1–6의 도입 원칙은 사용자 확정. 복습 간격·레거시 이전·구체적 저장/복구 계약은 후속 검토. 전체 설계 승인·구현 시작으로 간주하지 않음**
- LearnHarness 사실 근거: [지식 모델 조사](learnharness-knowledge-model.md), 커밋 `3dd52110bbcbcba81645453ce0a8fdc230594c47`의 정적 소스 분석
- 현재 합의: [decisions.md](decisions.md). 전체 초안은 [design-draft.md](design-draft.md) 참고
- 명시적 선택: `명제 중심으로 확정 (Recommended)`. 기존 ‘개념/원칙 기본 노드’ 제안을 저장·재사용의 기본 단위 기준으로 대체
- 추가 선택: `예시 수준 채택 (Recommended)`. 그림 2의 독립 주장과 설명·기록 분리 수준 채택
- 관계 선택: `이 구분으로 확정 (Recommended)`. 추론·선수 학습·적용 맥락 구분과 공동 전제·독립 논증 보존
- 수집·수정·학습 경험 선택: `1 - 나머지 5,6도 너가 권장한대로 진행`. 검토 4의 1안과 검토 5·6의 추천안 채택
- 다이어그램에 대한 ‘굿’ 피드백이 아니라 후속 명시적 선택들을 승인 근거로 사용. 여섯 항목 밖의 운영 세부·구현·실제 데이터 변경 권한까지 확대하지 않음

## 그림으로 검토

먼저 [우리 공부 노트는 어떻게 달라질까? — 쉬운 설명](learnharness-adoption-diagrams.html) 참고. **민수와 지우가 같은 숫자 10에 각각 1을 더하는 예시**부터 시작해, 중간 단계를 순서대로 설명.

쉽게 말하면 다음 여섯 가지입니다.

1. **제목만 남기지 않기:** ‘동시성’ 대신 ‘두 작업이 섞이면 증가 하나가 빠질 수 있다’처럼 배운 내용을 적습니다.
2. **필요한 만큼만 나누기:** 따로 물어보거나 고칠 내용은 나누고, 숫자 예시와 풀이는 설명 옆에 둡니다.
3. **선의 뜻 구별하기:** ‘왜 그런가’, ‘무엇부터 배우나’, ‘어디에 쓰나’는 서로 다릅니다.
4. **맞는지 확인하기:** 자료와 조건을 확인합니다. 아직 모르면 표시하고 정답으로 쓰지 않습니다. 내 답은 별도의 공부 기록에 남깁니다.
5. **고친 흔적 남기기:** 같은 뜻이면 모으고, 잘못된 설명은 이전 내용과 고친 이유를 남깁니다. 조건이 다르면 따로 둡니다.
6. **교재는 이어서 읽기:** 관련 내용을 한 설명이나 질문으로 묶습니다. 내가 실제로 보여 준 부분만 공부 기록에 남깁니다.

- 밝은 스타일의 단일 HTML + inline SVG. 다섯 그림에 각각 3–5개 상자, 폭 `960`, 높이는 내용에 맞춤. 좁은 화면에서는 그림·표 영역만 가로 스크롤
- 전문 용어와 LearnHarness 비교는 페이지 하단의 접어 둔 참고 설명에 배치. 상세 근거와 결정 기록은 이 Markdown 본문에 유지
- 여섯 원칙의 승인 상태는 그대로 유지. 쉬운 설명으로 바꾼 것이 전체 설계 승인이나 구현·실제 공부 자료 변경을 뜻하지 않음
- 아래 기록의 ‘그림 2’는 선택 당시 예시를 가리킴. 현재 쉬운 설명에서는 같은 분리 기준을 2번 비교표로 표현

## 채택한 도입 방향

**명제·추론 사슬을 내용 구조로 채택하고, 근거 확인·보수적 병합·수정 이력·교재·복습을 우리 학습 요구에 맞게 연결. LearnHarness 전체 앱의 복제나 코드·프롬프트 복사는 전제하지 않음.**

| 역할 | 채택한 방향 | 구분 이유 |
|---|---|---|
| 지식 원본 | 조건과 출처를 가진 명제 + 전제 묶음→결론 | 같은 주장 재사용과 추론의 대상 명확화 |
| 주제·개념 탐색 | 이름·태그·목록 등 가벼운 묶음 | 별도 개념 원본을 추가하지 않고 읽기 쉬운 탐색 제공 |
| 이번 학습 순서 | 프로젝트·챕터의 학습 경로 | 학습 순서와 논리적 함의 혼동 방지 |
| 실제 이해·적용 근거 | 원 응답·힌트·실행·시점·맥락·명제 버전 | 지식 기록과 학습자 수행 구분 |
| 단권화 교재 | 명제의 설명 + 연결 문장·예시·프로젝트 맥락 | 명제 목록이 아니라 독립적으로 읽을 수 있는 교재 유지 |
| 복습 | 명제별 일정·근거, 연관 항목을 묶은 회상 세션 | 내용 중복은 줄이고 질문 파편화는 방지 |

이 표의 ‘역할’은 반드시 같은 수의 폴더·서비스·엔티티를 만든다는 의미가 아님. 실제 저장 형식은 최소 구현으로 설계.

## 이미 결정한 범위

다시 선택받을 항목이 아님:

- 하나의 study 루트, PC별 절대 경로 독립, 기존 `study-*` 위치 유지
- 공통 지식은 루트에서 관리. 프로젝트는 지식 참조와 고유 맥락 보유
- 지식의 기본 단위는 명제. 주장·조건·범위를 저장·재사용의 기준으로 사용하고 큰 개념은 이름·태그·목록으로 탐색
- 독립적으로 참조·검증·질문·수정할 주장은 분리. 재사용할 정의·규칙·판단 기준은 보존하고 설명·예시·실행 로그는 관련 설명·프로젝트 기록에 유지
- 추론·선수 학습·적용 맥락의 의미 구분. 공동 전제 묶음과 같은 결론의 독립 논증 보존
- 자료·교재·교사 설명에서 후보 수집 후 근거·조건 확인. 미확정도 보존하되 확정 교재·채점 기준으로의 사용 보류
- 학습자 원 응답은 수행 근거로 별도 보존. 실제 확인한 명제·당시 버전·맥락에만 연결
- 추가·의미 수정·병합은 자동 반영 후 사후 검토. 표현 추가·같은 지식의 교정·별도 주장을 구분하고 이력 보존
- README에 공통 설명을 포함하고 관리 영역 자동 최신화
- 명제별 통합 복습, 프로젝트·챕터는 범위 필터. 교재와 질문은 연관 명제를 묶어 구성, 새 맥락에서 읽었다는 이유만으로 일정 이동 금지
- 진단 기본 상한 8문항, 개념 후 프로젝트 실습, HTML 완료 시험
- Pi의 작은 상태 위젯과 필요할 때 여는 지도

**검토 1–6은 확정한 방향과 원칙의 기록. 남은 작업은 이를 실현하는 저장·일정·이전·복구 계약 설계이며, 이미 선택한 원칙을 다시 선택받지 않음.**

## 검토 1 — 지식의 기본 단위

**확정: 명제를 저장·재사용의 기본 단위로 사용. 사용자 선택은 `명제 중심으로 확정 (Recommended)`. 이 선택 자체가 분해 수준·복습 운영 정책의 승인을 뜻하지 않음. 분해 수준은 검토 2의 별도 선택으로 확정.**

- LearnHarness: 짧은 `name`과 정밀한 `statement`를 가진 명제 하나가 영구 노드. 별도 Concept 계층 없음
- **결정:** 명제를 기본 단위로 채택. 이름은 표시용, 동일성은 주장·조건·범위로 판단
- 개념은 우선 탐색용 이름·태그·목록으로 표현. 별도 개념 객체와 명제 목록의 2계층은 도입하지 않음
- 설명·예시까지 문장마다 노드로 나누지는 않음. 채택한 분리 기준은 검토 2에 기록
- 미채택 대안: 개념 객체 아래 명제를 배치. 큰 주제 단위 탐색에 명시적인 구조를 주지만 개념의 중복·경계·명제 소속까지 별도 관리 필요

예시:

- 탐색 이름: **복합 동작의 원자성**
- 저장할 주장: **개별 연산의 원자성만으로 여러 연산을 묶은 전체 동작의 원자성이 보장되지는 않음**
- 다른 주장: **주어진 단순 읽기/쓰기 모델에서 두 작업이 같은 값을 읽고 각각 1을 더해 덮어쓰면 갱신 하나가 유실됨**

두 주장은 관련 있지만 동일하지 않으므로 같은 ‘원자성’ 이름 아래 나온다는 이유만으로 하나로 병합하지 않음. 기존 그림의 K17 등 ID는 설명용이며 실제 명제 분해·ID 계약 아님.

## 검토 2 — 노드로 남길 내용의 범위

**확정: 그림 2의 예시 수준 채택. 사용자 선택은 `예시 수준 채택 (Recommended)`. 독립적으로 재사용할 주장은 나누고 설명·예시는 함께 보존.**

- LearnHarness: 자립적인 핵심 아이디어, 논증에서 역할을 하는 내용 위주. 불필요한 예시·기호 풀이·재진술 제외. 연결 없는 중요한 명제는 보존 가능
- **결정:** 논증이 없어도 독립적으로 설명·판단·적용에 재사용할 정의·규칙·판단 기준은 명제로 보존
- 설명용 예시·풀이·비유·일회성 실행 결과는 관련 명제의 설명이나 프로젝트 기록으로 보존. 모든 문장을 노드로 만들지 않음
- 일반적인 규칙으로 승격할 때는 조건과 근거를 확인. 예제 한 번의 결과를 보편 명제로 전환하지 않음
- 미채택 대안: 영구 그래프를 도출 가능한 핵심 주장에 좁게 한정. 작은 그래프에는 유리하지만 절차·실무 판단·비논증형 학습 내용의 재사용은 별도 경로 필요

채택한 분리 기준:

- 둘을 서로 다른 프로젝트에서 따로 참조할 필요가 있는가?
- 한쪽만 성립하거나 한쪽만 잘못될 수 있는가?
- 독립적으로 물어보거나 수정해야 하는가?

독립적으로 다룰 필요가 있으면 분리하되, 형식 논리의 모든 원자식까지 쪼개지는 않음. 한 명제를 설명하는 여러 문장과 예시는 함께 유지 가능. 정확한 분해는 에이전트가 수행. 채택한 예시 수준은 모든 개별 추출 결과의 정확성을 보증하거나 수집·검증 절차까지 확정한 것이 아님.

## 검토 3 — 추론과 학습 순서의 분리

**확정: 추론·선수 학습·적용 맥락의 의미 구분. 사용자 선택은 `이 구분으로 확정 (Recommended)`. 지도에서는 필요에 따라 함께 탐색.**

- LearnHarness: 영구 그래프는 `A ∧ B ⇒ C`, 수업 지도는 별도 PlanTree의 선수 관계
- **결정:** 영구 명제 간 추론, 목표별 학습 경로, 프로젝트별 적용 연결을 각각 식별
- ‘이것을 먼저 배운다’가 ‘이것으로 다음 명제가 증명된다’는 뜻이 아님
- 프로젝트 활용도 논증이 아니라 맥락 연결. 단순 관련·역사적 순서를 추론으로 저장하지 않음
- 서로 다른 논증이 같은 결론에 도달하면 별도 사슬. 공동 전제의 묶음 보존
- 학습 경로 지점 하나는 명제 여러 개를 참조할 수 있고, 같은 명제를 서로 다른 경로에서 활용 가능
- 학습 순서는 목표·학습자에 따라 조절. 선수 학습을 건너뛰는 것과 논리적 전제를 제거하는 것을 구분
- 적용 연결 자체를 이해 완료로 해석하지 않음. 실제 설명·적용 여부는 수행 근거로 별도 확인
- 화면·저장 방식은 미결. 하나의 타입 있는 그래프에 함께 저장하는 구현도 가능하나, 관계 의미와 목표별 학습 경로의 독립성은 유지

물리적으로 파일을 몇 개로 나눌지는 구현 문제. 여기서의 결정은 **관계의 의미와 학습 경로의 독립성**에 관한 것.

## 검토 4 — 수집 대상과 정확성 확인

**확정: 검토 4의 1안 채택. 자료·조건·근거를 확인하고 미확정 후보는 보존하되, 확정 교재·정답 기준으로의 사용은 보류.**

- LearnHarness: 교사 설명과 가져온 노트에서 추출. 감사기는 원문 사실성이나 추론을 재검증하지 않고 동일성만 판단
- **결정:** 사용자 제공 자료·학습 교재·교사 설명을 후보 입력으로 사용하되, 출처와 조건을 점검한 결과를 구분
- 사용자 답변은 기본적으로 학습 근거. 틀린 답도 원 응답으로 보존하며, 맞았다는 이유만으로 공통 지식 원본에 자동 승격하지 않음
- 사용자가 별도로 지식 자료로 지정한 개인 노트는 수집 가능. ‘학습 답변’과 ‘입력 자료’의 역할 구분
- 자료에 명시된 내용, 자료에서 도출한 해석, 에이전트가 제안한 가설을 섞지 않음. 확인되지 않은 항목은 미확정 표시
- 미확정도 저장할 수 있으나 확정 교재·채점 기준으로 조용히 사용하지 않음. 논증 연결이 부족하면 사슬을 꾸며내지 않고 독립 명제로 남김
- 출처가 있다는 사실만으로 참을 인증하지 않음. 자동 확인도 오류 가능성이 있는 검토이며 수학적 증명기가 아님
- 비용: 추가 자료 확인과 처리 시간. 대신 중앙 오정보가 여러 프로젝트·시험으로 퍼질 위험 감소

자동 반영 후 검토는 유지. 모든 후보를 사용자 사전 승인 대상으로 바꾸자는 제안이 아님. 추출·근거 검토·동일성 판정·저장의 책임은 구분하되 반드시 네 개의 에이전트 프로세스를 만들 필요는 없음.

## 검토 5 — 동일성 판단과 내용 수정

**확정: 사용자 요청에 따라 검토 5 추천안 채택. 보수적 동일성 판단, 표현 추가·내용 교정·별도 주장의 구분, 과거 버전·답안 보존.**

- LearnHarness: 동일 주장의 관점·정밀도 차이까지 적극 연결. 최초 statement는 유지하고 이후 표현은 aliases로 누적
- **결정:** 자동 반영 정책은 유지하되 조건·대상·버전이 다르면 성급히 합치지 않음. 확신이 부족하면 별도 후보로 보존
- 같은 의미의 표현: 기존 ID에 표현·출처 추가
- 같은 주장을 더 정확히 설명하거나 잘못된 내용을 교정: 변경 전후·이유를 남긴 새 버전. 이전 답안은 당시 버전에 유지
- 적용 범위가 다른 주장: 별도 ID로 유지. ‘A와 관련’ 또는 ‘더 좁은 조건’인 것을 ‘A와 동일’로 취급하지 않음
- 잘못된 병합을 풀 때 이전 ID·출처·학습 근거의 연결 복구. 관련 없는 진도까지 되돌리지 않음
- 문법적·파일 구조 검증은 코드, 의미 동일성은 에이전트 판단. 모호한 사례의 오병합을 테스트 몇 개로 완전히 방지한다고 주장하지 않음

미채택 대안은 원본처럼 병합을 더 적극적으로 하는 것. 중복은 줄지만 조건이 다른 주장을 잃을 위험 증가. **자동화의 정도와 병합의 엄격함은 별개의 선택.**

## 검토 6 — 교재와 복습에서 사용하는 단위

**확정: 사용자 요청에 따라 검토 6 추천안 채택. 저장·일정은 명제 단위로 관리하되 교재·질문은 맥락별로 묶고, 실제 확인한 범위에만 수행 근거 연결.**

- LearnHarness: 저장 명제·사슬에서 그래프/표와 연습 맥락을 구성. 현재 study의 단권화 자동 갱신·통합 복습 요구와 같지는 않음
- **결정:** README는 명제 목록이 아니라 설명의 흐름을 갖춘 교재로 유지. 연결 문장·예시와 프로젝트 맥락을 함께 제공
- 명제 하나마다 카드 하나·질문 하나·파일 하나를 강제하지 않음
- 복습 일정은 명제 ID 기준으로 통합하되, 연관 명제는 한 설명·문제로 함께 확인 가능
- 답변 하나가 여러 명제를 다뤘다면 실제 확인된 범위에만 근거 연결. 주제 전체를 일괄 이해 완료로 처리하지 않음
- 전체 추론 능력은 사슬/복합 과제의 수행 근거로 별도 확인. 전제들을 각각 외운 것과 논증을 독립 수행한 것은 다름
- 동일 원리를 다른 프로젝트에서 적용한 근거는 맥락별로 보존. 새로운 맥락에서 봤다는 이유만으로 다음 복습 날짜를 자동으로 미루지 않음
- 미채택 대안: 복습을 개념/단원 묶음 단위로만 관리. 일정은 단순해지지만 어떤 주장을 기억하고 어떤 부분이 미확인인지 더 거칠게 기록됨

복습 간격·질문 수·최초 기준일·기존 회차 이전은 후속 정책 검토. 명제 단위 채택이 자동 간격 알고리즘 승인이나 실제 일정 변경을 뜻하지 않음.
