study 학습 플로우 한눈에 보기

챕터 하나를 배우는 흐름과, 그 챕터가 끝났을 때 내 교과서(book)가 만들어지는 흐름을 두 장으로 나눴습니다. 주황색이 이번 고도화로 새로 생긴 핵심 지점입니다.

1. 한 챕터의 학습 흐름

학습자는 승인·응시·열람만 하고, 나머지는 에이전트와 extension이 이어 받습니다.

  1. 시작 — /study-init로 배치 진단을 하고 커리큘럼을 승인하면 study 루트에 프로젝트가 등록됩니다.
  2. 진단 → 개념 → 실습 — /study-chapter 메뉴의 "이어서"로 진행합니다. 개념 단계에서 확인된 지식(명제)이 knowledge/items에 쌓이고, 실습은 실제 테스트 실행으로 검증합니다.
  3. 시험 — 브라우저 시험에 통과하고 결과를 확인하면 챕터 완료입니다.
  4. 완료 후 (두 갈래) — extension은 챕터 지식마다 복습 일정(+1·+3·+7·+14일)을 등록하고, 에이전트는 이 챕터를 교과서로 재구성합니다(아래 2번 그림).
  5. 열람 — 교과서가 바뀔 때마다 HTML이 다시 빌드되고, /study-book [개념]으로 엽니다. 복습은 예정일에 /study-review로 합니다.

2. 챕터 완료 → 내 교과서

에이전트는 재료를 읽고 개념 단위로 다시 쓰며, 정본은 Git에, 생성물은 자동으로 다시 만들어집니다.

  1. 정리 지시 — 시험이 끝나면 extension이 # STUDY_BOOK_PENDING을 보냅니다. 실패하거나 중단되면 "정리 대기"로 남고 /study-chapter 메뉴에서 이어서 합니다.
  2. 배치 계획 — study_book plan이 이 챕터의 명제가 이미 어느 페이지에 있는지(보강 대상), 아직 없는 명제, 재료 경로를 알려 줍니다. 정답은 담지 않습니다.
  3. 재구성 — 챕터 README·풀었던 문제·실습 결과를 읽고 개념 단위로 나눠 다시 씁니다. 같은 개념이면 새 페이지 대신 기존 페이지를 보강합니다.
  4. 적용 — 하위 개념 생성·명제 배치·본문·배운 곳을 study_book apply 한 묶음으로 원자적으로 저장합니다. 결과로 차이 링크와 undo용 changeId가 나옵니다.
  5. 자동 재생성 — book/README.md 대시보드와 .study/local/book-site(HTML·차이 페이지)가 다시 만들어집니다. 실패해도 저장은 유지되고 경고만 납니다.
